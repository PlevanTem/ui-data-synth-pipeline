# Spec：五合一支付前台模板（index 710）

## 用户与场景

- **场景**：半成品支付/订单前台经二次开发与细节修复后，需以**单页 HTML5** 形式展示五套平台风格模板（美团、京东、拼多多、滴滴、携程），便于对照验收与演示。
- **使用者**：产品/前端/外包验收方；需在桌面与移动端快速切换模板、查看订单—支付相关能力说明。
- **痛点**：市面多版本存在交互与文案细节缺陷；本交付强调**可核对**的流程状态与文档体说明。

## 核心问题（一句话）

> 在统一壳层内，用**可切换的五套独立标题模板** + **六类能力矩阵**，把支付相关订单状态讲清楚、可点、可模拟，并承载版本优势的说明文案。

## 功能推导

### 显性功能

1. 五平台模板切换（独立页面标题 `document.title` 与页内主标题同步变更）。
2. 六格矩阵：`支付状态` / `订单取消` / `订单发货` / `订单过期` / `支付成功` / `跳转官网` — 可点击展开详情或切换模拟状态。
3. 模拟：支付状态（待支付 / 处理中 / 成功 / 失败）、订单过期倒计时重置、取消确认、发货时间线占位。
4. 「跳转官网」为外链按钮（`example.com` 占位，新窗口，`rel="noopener noreferrer"`）。

### 隐性功能

- 响应式：≥44px 触控目标；正文 ≥24px（`text-base` 以上为主）。
- 聚焦环、`aria` 对切换与矩阵按钮；减少动画依赖（ prefers-reduced-motion 可关动画）。
- 无未处理控制台错误；静态 `file://` 下尽量可阅（主要交互不依赖 HTTP）。

## 设计约束

- **文档体（doce / doc tone）**：条款化、编号、定义—说明—操作结构；避免口语堆砌。
- **品牌**：使用**近似色**与命名暗示，不宣称官方背书；无真实商标素材。
- **技术**：`02-build/index.html` 单文件；Tailwind CDN + 原生 JS；与 `case-manifest` 的 `single_html` 一致。

## 假设

- 「doce language」按 **正式文档体中文** 实现；若用户原意为其他自然语言，可在 brief 迭代中替换词条表。
- 外链官网使用占位域，避免绑定真实生产域名。
