# 设计防坑指南 (Design Guardrails)

本文档记录 Web Design Pipeline 在生成 `design_brief.md` 与最终前端页面时，必须遵守的视觉与交互设计红线。Designer Agent 在产出设计系统时必须逐条对照检查；Frontend Agent 在实现时如发现违反这些规则，应反馈而非盲目执行。

> 本文聚焦**设计原则**（看起来对不对、用起来是否合理），与 `engineering-guardrails.md`（代码层面如何不踩坑）互补。

---

## 1. 视觉重心与信息层级

页面应有明确的视觉重心和信息层级，**不允许同等权重平铺**。

- 重要信息（紧急状态、核心操作、关键数据）通过**字号放大**、**色彩加重**、**字重提升**、**位置突出**等方式强化
- 次要信息（时间戳、辅助说明、状态标签）弱化处理（降饱和度、缩字号、降字重）
- 不同状态区块（如待办 / 进行中 / 已完成）必须有**视觉差异化**——通过色彩、透明度、装饰元素区分，禁止只靠文字标签区分
- 一个页面应能让用户在 1 秒内识别"最重要的事是什么"

**反例**：所有卡片同样大小、同样颜色，只靠左上角小标签区分状态。

---

## 2. 色彩使用纪律

### 2.1 色彩必须有功能目的
- 色彩使用应有明确**功能目的**（状态标识、操作引导、品牌识别）
- **不为装饰而随意加色**——每个非中性色都要回答"它在表达什么状态/语义"
- 如**无明确指令要求，默认使用**内敛克制的用色、中性的配色比例和柔和的材质；避免过度用色、夸张的配色比例、生硬的材质，保持共性而非个性，调性平衡，无性别或文化倾向性

### 2.2 渐变色使用范围
- 渐变如需使用，应放在**视觉焦点位置**（核心 CTA 按钮、Hero 关键元素、品牌图形）
- **禁止**用渐变做大面积背景（除非是极简极淡的氛围渐变，且不与内容争夺注意力）
- 不要用紫蓝渐变这类已被滥用的组合，除非有明确的差异化处理

### 2.3 背景色定位
- 背景色应起**衬托内容**作用，不应抢内容的视觉注意力
- 大面积高饱和背景 = 红线

### 2.4 配色禁忌
- 红配紫、荧光绿配粉、霓虹蓝紫等**视觉禁忌组合**禁止使用
- 不使用未经过设计师筛选的"原生"高饱和色（如 `#FF0000` 纯红、`#0000FF` 纯蓝），统一走 OKLCH 色阶或品牌色板
- 主色数量控制在 1 个主品牌色 + 1-2 个辅助/次要色 + 语义色（success/warning/error/info）

### 2.5 主题色切换处理
- 切换主题色时，灰色区域应**叠加 5-10% 的背景色**，使色调跟随背景一起变化保持统一
- 禁止主题切换后仍用纯灰，会显得割裂

---

## 3. 对比度与可读性

- 文字与背景对比度需满足 **WCAG AA 标准**（正文 ≥ 4.5:1，大字号 ≥ 3:1）
- **手机端最小字体不低于 16px** （正文场景，标签/辅助信息可下沉到 12-14px 但需保证可读）
- 时间、编号、辅助信息**虽可弱化但不应不可读**（最低对比度 3:1）
- 深色模式必须**单独校验对比度**，不要假设浅色方案换个反色就能用
- placeholder、disabled 状态也要保证可读，不能淡到完全看不清

---

## 4. 对齐、间距、圆角的系统化

### 4.1 对齐
- 同层级元素**必须严格对齐**：标题对齐、卡片高度一致、按钮基线对齐
- 列表中的图标、文字、操作按钮要在统一的视觉轴线上

### 4.2 间距系统
- 间距采用**系统化节奏**（如 4dp / 8dp / 16dp / 24dp / 32dp / 48dp / 64dp）
- 禁止出现 7px、13px、19px 这类非系统值
- 内外边距层级关系正确：**外层间距 ≤ 内层间距**（符合树形结构认知，外松内紧）

### 4.3 圆角
- 同类组件圆角**保持统一**（所有按钮同圆角、所有卡片同圆角）
- 圆角随组件大小自适应——大卡片大圆角，小标签小圆角，但同尺度下保持一致
- 推荐 Apple Squircle（超椭圆）连续曲率而非标准 `border-radius`，避免尖锐的棱角

---

## 5. 信息密度与必要性

- 页面信息应经过筛选，**只保留对当前场景有价值的内容**
- **如无必要勿增实体**——每个元素、文本、标签都应有存在理由；问"删掉它会不会丢信息？"
- 适当**留白控制信息密度**（呼吸感来自留白比例而不是元素数量）
- 高级功能 / 设置 / 不常用操作应**下钻到二级页面**或抽屉/弹窗，不外露干扰主流程

---

## 6. B端与C端的差异化

- **B端**：追求效率和信息密度，可有数据表、密集仪表板、多列布局
- **C端**：追求简洁和友好，重点突出，操作元素更大更易点击
- **工具类小应用**（番茄钟、待办、计算器）：**轻量化、情感化**，不应做成仪表板或控制台

> 判定标准：先看 `prdSpec.json` 的 `target_user` 和 `usage_context`。给企业用户用的就别套消费品风格；给个人用户用的就别套 admin dashboard 范式。

---

## 7. Emoji 与图标使用

- **Emoji 仅用于点缀**（情感化文案、装饰性元素），不可大面积铺设
- 功能图标必须使用**统一风格的标准 icon 库**（Lucide / Heroicons / Phosphor / Material Symbols 等），**不用 Emoji 替代功能图标**
- 扁平插画 / SVG 图标的视觉表达力优于 Emoji
- 图标语义需**准确匹配功能**——别把 🚀 当"导出"图标，别把 🔥 当"删除"图标

---

## 8. 端适配（移动 / Web / 桌面窗口）
- 构建跨产品的体验一致性，兼顾设计元素、交互方式的一致，同时考虑不同设备形态、不同使用场景的差异，进行多场景统一的设计思考，在用户操作流程上保持连续性，保证跨产品无缝连贯的用户体验。
- **明确目标端**：手机 / 平板 / Web / 桌面 App 窗口，按对应端的设计范式处理
- 移动端**不应出现 PC 端的滚动条、上下箭头、hover 提示**等控件
- 手机端字体、点击热区需适配触控操作（**触控目标最小 44×44 px**）
- 不同端的宽度比例、内容密度应有差异化处理：
  - 手机：单列、纵向滚动、底部固定操作
  - Web：栅格化、横向呼吸、悬浮交互
  - 桌面 App 窗口：紧凑工具栏、快捷键提示

---

## 9. 组件一致性 / 设计系统思维

- 同类组件**抽象为统一规则**：相同内边距、圆角、视觉布局
- **避免**"有的卡片有投影、有的没有"、"有的按钮带边框、有的不带"等不一致问题
- 组件应**可复用**，风格全局统一
- 在 `design_brief.md` 的 Component Stylings 章节为每类组件定义唯一规范，并在实现时严格遵守

---

## 10. 情感化设计 / 氛围塑造

- 工具类 / 生活类应用必须有**情感化设计**——通过配色、品牌元素、主题一致性营造氛围
- 例：番茄钟应给人**安静专注的沉浸感**，而非普通秒表的工业感
- C端应用的差异化设计是用户**愿意付费**的核心要素之一
- 在风格探索阶段，必须明确写出"这个产品的情绪温度是什么"

---

## 11. 卡片嵌套层级

- **避免三层及以上卡片嵌套**（卡片里套卡片里套卡片 = 红线）
- 已有标题做区块划分时，**不需再用卡片边框重复分割**
- 层级关系用**间距和标题**即可表达，不必严丝合缝画框
- 区块分隔的优先级：留白 > 标题 > 细分割线 > 卡片背景 > 卡片描边

---

## 12. 投影 / 阴影物理规律

- 投影应符合**物理规律**：Y 轴偏移、模糊半径、透明度三者**成正比变化**
- 卡片**离背景近** = 投影**实而小**（小 Y 偏移、小模糊、低透明度）
- 卡片**离背景远** = 投影**虚而大**（大 Y 偏移、大模糊、稍高透明度）
- 按钮投影建议带**品牌色**（彩色投影），增加层次和品牌感
- 参考 Material Design Elevation 或 鸿蒙 HIG 投影规范，**不要凭感觉写 `0 4px 6px rgba(0,0,0,0.1)`**
- 推荐至少定义 3-4 档：Flat / Raised / Floating / Modal

---

## 13. 视觉权重与色块使用
- 中性内敛、自然直觉、和谐一致
- **头像**作为次要信息，不应使用大面积高饱和色块（避免抢主内容注意力）
- 强调应通过**文字（字号 / 字重）** 而非色块来做
- **色块留给状态标识**（如待办标签、状态徽章），不要用色块做装饰
- 视觉权重分配应与信息重要性匹配——重要的事大而显眼，次要的事小而克制

---

## 14. 深色模式分隔策略

- 深色模式下**慎用明显线条做分割**，会显得生硬
- 优先用**间距、透明度差异、轻微背景色变化**替代分隔线
- 分割方式需与整体设计语言一致——Light / Dark 模式要**统一考虑**，不能 Light 用线分割、Dark 又用块分割

---

## 15. 插画与头像细节

- 小尺寸插画应**精简细节**，不宜过于复杂（小图标里塞太多线 = 视觉糊）
- 头像需与背景**有明确区分**：加描边 / 加底色 / 整体压暗 5-10%
- 同一界面内头像**裁切规则一致**（圆形或圆角矩形选一种，全用同一种）

---

## 16. 导航控件位置

- Tab / Segment 分类器应放在页面**顶部或底部固定位置**
- **禁止**把 Tab 嵌在 ScrollView 中间（用户滚动时分类器消失，体验割裂）
- 移动端导航应遵循平台设计规范（iOS HIG / Material Design）

---

## 18. 写入 `design_brief.md` 时的硬要求

为了让 Frontend Agent 也能受益于这份 guardrails：

1. 在 `design_brief.md` 的 **Do's and Don'ts** 章节，必须**显式列出**本案应用了哪些 guardrails 条款（按编号引用，例如 "遵守 §2 渐变仅用于 CTA"），以及刻意规避了哪些反模式
2. 在 **Component Stylings** 章节，每个组件必须明确**圆角、内边距、阴影**的具体值（与 §4、§9、§12 一致）
3. 在 **Color Palette & Roles** 章节，每个非中性色必须写明**功能角色**（与 §2.1 一致）
4. 在 **Responsive Behavior** 章节，必须区分目标端并给出对应触控目标 / 字号底线（与 §3、§8 一致）
