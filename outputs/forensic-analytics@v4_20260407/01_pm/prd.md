# ForensicAppraise - Case Volume & Resource Analytics Dashboard PRD

## 核心问题定义
帮助省级司法鉴定中心的主检法医师与管理者，实时监控不同法医学类别的鉴定人（受检者）流量与案件所处阶段，从而精准调度专业医疗设备，防范案件积压。

## 用户与场景分析
- **用户类型**：主检法医师（如 Dr. Li）、鉴定中心排班与资源调度管理人员。
- **使用场景**：每日晨会进行资源统筹；应对突发大规模案件（如重大交通事故）时的紧急设备调度；日常巡查各鉴定环节（初审、体检、报告出具）的通畅度。
- **痛点**：缺乏全局视野，难以直观预判季节性或特定伤害类型（如交通事故损伤、医疗过错）的流量高峰；无法迅速定位当前排队管线中哪个环节（如特定仪器的体格检查）出现了瓶颈；患者等待时间长导致体验不佳。
- **目标结果**：提升部门工作负载透明度至 100%，消除信息黑盒；缩短受检者（鉴定人）排队等待时间 20%。

## 设计意图
- **情绪目标**：打开后第一感受是“一切尽在掌握的秩序感”，使用过程中的基调为“专业、冷静、精准”。不可出现娱乐化或过度活泼的设计。
- **信息密度**：high（作为核心调度 Dashboard，需在一屏内聚合时间趋势、分类分布、流程漏斗等多个维度的数据，但需通过排版确保主次分明）。
- **交互深度**：moderate（主要交互集中在数据图表的悬浮查看、以及预估工具的表单计算与即时反馈）。
- **视觉信任感**：professional & utilitarian（兼具医疗的严谨与司法鉴定的权威，依靠精确的数字排版和克制的色彩传递信任）。

## 功能契约

### Must Deliver（M）
| ID | 功能 | 验收条件 | 失败条件 | 表现力目标 |
|----|------|---------|---------|-----------|
| M01 | 流量时间趋势分析 (Temporal Volume Analytics) | 呈现折线图或柱状图，展示日/月维度的鉴定人数量变化趋势。 | 图表重叠不可读，或未体现时间轴属性。 | 具备平滑的数据载入动画，悬浮(hover)时有清晰的十字准线或数据提示框(Tooltip)，图表呈现高信噪比。 |
| M02 | 伤害类型分布地图 (Injury Distribution Mapping) | 呈现饼图/环形图或矩形树图，清晰拆解“交通事故”、“医疗过错”、“职业伤残”等类别的占比。 | 类别颜色难以区分，或小占比数据无法查看。 | 色彩符合司法医疗属性（克制且具区分度），图表区块交互响应干脆，支持图例联动。 |
| M03 | 案件状态流转管线 (Case Status Flow) | 可视化呈现“初次登记” -> “体格检查” -> “最终报告出具”三个核心阶段的当前积压人数（如漏斗图或流转卡片）。 | 无法一眼识别哪个环节人数最多/出现拥堵。 | 利用视觉隐喻（如管道粗细、颜色警告）展现流动感与拥堵预警（如红色微动效提示超载）。 |
| M04 | 鉴定时间线预估器 (Appraisal Timeline Estimator) | 提供输入框（当前排队人数）与下拉/滑块（案件复杂度），即时输出 AI 估算的完成日期/所需时长。 | 缺乏对非数字或异常输入的错误处理，或无即时计算反馈。 | 表单交互流畅丝滑，计算结果展现带有“智能演算”的微动效反馈，增强科技感。 |

### Should Deliver（S）
| ID | 功能 | 理想形态 | 降级底线 |
|----|------|---------|---------|
| S01 | 全局核心指标看板 (Global Metric Cards) | 提炼关键数据（总等待人数、本周新增、设备利用预警等），带有同环比涨跌趋势微图表（Sparkline）。 | 仅展示当前的绝对数值，无趋势对比。 |
| S02 | 数据警报机制 | 当某环节积压人数超过阈值时，Dashboard 对应区块出现呼吸灯式的高亮警报。 | 仅用静态的红色字体或红点标识。 |

### Excluded（X）
| ID | 功能 | 排除原因 |
|----|------|---------|
| X01 | 具体案件档案录入与详情编辑 | 本系统定位为宏观流量与资源 Analytics Dashboard，而非 EHR/LIS 业务操作后台。应避免引入繁杂的表单与长文本处理。 |
| X02 | 用户角色权限管理系统 (RBAC) | 对于单页数据合成与展示 demo，登录与权限分配不在当前核心调度价值验证路径内。 |

## 内容意图地图（IA）

### 顶部概览与指标区 (Top Global Metrics)
- **意图**：提供定海神针式的全局状态确认，一秒判断当前中心是否处于超载状态。
- **优先级**：P0
- **必须包含**：Dashboard 标题、总鉴定人数、平均等待时长估算值、紧急积压警告（如有）。
- **创作自由度**：content-fixed-layout-free
- **关联契约**：S01, S02

### 流量与类别洞察区 (Volume & Distribution Insights)
- **意图**：分析高峰期规律，明确当前主要消耗医疗设备的是哪类伤害鉴定。
- **优先级**：P0
- **必须包含**：时间维度流量图表（Temporal Volume Analytics）、伤害类型分布图（Injury Distribution Mapping）。
- **创作自由度**：fully-open
- **关联契约**：M01, M02

### 流程管线监控区 (Pipeline Monitoring)
- **意图**：定位业务流程中的物理瓶颈（通常在体格检查或特定设备使用环节）。
- **优先级**：P1
- **必须包含**：包含“初次登记”、“体格检查”、“报告出具”三大节点的流转可视化组件及各节点实时人数。
- **创作自由度**：content-fixed-layout-free
- **关联契约**：M03

### 智能排班辅助区 (Timeline Estimator Tool)
- **意图**：基于当前流量池和复杂度，辅助主检医师进行干预和预期管理。
- **优先级**：P1
- **必须包含**：操作面板（包含人数输入、复杂度选择）、醒目的预计完成时间结果展示区。
- **创作自由度**：fully-open
- **关联契约**：M04

## 响应式优先级
**desktop-first**。该场景为主检医师在办公室使用桌面显示器进行全局监控和早会投屏。在 Tablet 端需保证模块可读性（堆叠或双列），Mobile 端非核心场景，仅需保证基础内容不溢出即可。

## 技术约束
- 必须且仅限于单文件 HTML 实现。
- 使用 Tailwind CSS CDN 进行样式构建。
- 使用原生 JavaScript（Vanilla JS）处理逻辑与数据可视化，严禁引入 React/Vue 等框架。
- 数据可视化如需引入库（如 Chart.js, ECharts, 或 Recharts 的原生替代），必须通过 CDN 引入并保证单文件运行环境。

## 设计约束
- **色彩规范**：契合司法与医疗的双重属性。主色调建议采用科技/司法蓝（如 Slate 或 Indigo 系），状态色需明确：绿色代表畅通/正常，橙/红色用于警示案件积压与设备瓶颈。
- **字体排版**：强制采用系统级无衬线字体（如 Inter, Roboto），数据看板需采用 Tabular Nums（等宽数字）以对齐关键指标，确保专业场景下对数字变化的高度敏感性。
