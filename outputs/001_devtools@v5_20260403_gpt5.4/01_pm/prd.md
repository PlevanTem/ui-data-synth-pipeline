# 性能透视（DevTools）PRD

## 核心问题定义

帮助负责性能与稳定性的工程角色在生产或准生产场景下，把「海量遥测与剖析数据」快速收敛为可定位的瓶颈假设与可沟通的结论，并在不牺牲大规模可视化的前提下完成下钻、对比与自然语言式探查。

## 用户与场景分析

- **用户类型**：后端/全栈工程师、SRE、性能专项、技术负责人；次要用户为临时参与排障的前端或数据工程师。
- **使用场景**：线上或预发环境出现延迟尖刺、吞吐下降、资源争用；版本发布前后的回归对比；容量规划前的热点识别。
- **痛点**：指标与 trace 体量大，传统表格与静态图难以同时呈现「全局分布」与「局部细节」；切换工具链成本高；口述需求与书面筛选条件不一致导致重复操作。
- **目标结果**：在单一工作区内完成从宏观态势 → 维度下钻 → 证据摘录的闭环，输出可复现的查询条件与视图状态，支撑后续修复或评审。

## 设计意图

- **情绪目标**：首屏即感到「数据被驯服」——重数据有清晰进度与层次，而非黑屏等待；使用过程中保持专注、可控，关键变化有可预期的动效反馈而非干扰。
- **信息密度**：high
- **交互深度**：rich
- **视觉信任感**：professional（在软 UI 风格下仍需传达工程可信度：层级清楚、状态明确、对比度满足长时间盯屏）

## 功能契约

### Must Deliver（M）

| ID | 功能 | 验收条件 | 失败条件 | 表现力目标 |
|----|------|---------|---------|-----------|
| M01 | 大规模数据 WebGL 渲染层 | 在文档约定的基准数据量级下（例如 ≥10⁴ 可交互点/片元负载的演示集），主画布可完成初始化并支持平移/缩放/框选或等价空间导航；帧时间可感知卡顿时有明确的降级或采样提示而非静默卡死 | 超过基准量级即崩溃、白屏、或交互无响应超过 5s 且无说明 | 空间导航动效与 LOD/聚合切换有编排（淡入淡出或短时过渡），层级焦点变化可读 |
| M02 | 动态 SVG 指标视图 | 至少两类不同语义的时间序列或分布类视图可随同一数据集或关联数据集联动更新；数据变化时轴线、路径或标记以可辨认的过渡更新（非整图闪烁替换） | 数据刷新导致 SVG 结构错乱、坐标轴标签重叠不可读、或联动逻辑静默失效 | 微交互限于 200–400ms 量级的过渡与 hover 反馈，避免与 WebGL 层抢注意力 |
| M03 | 自然语言查询入口 | 用户可用文本描述筛选/聚合意图（示例：按服务、时间段、百分位），系统返回可解析的查询摘要或可编辑的条件面板等价物；无效输入给出可行动的纠错提示 | 任意输入均被静默忽略或仅返回通用错误文案 | 查询提交 → 结果呈现之间有阶段性加载与状态条，文案与动效一致 |
| M04 | 暗黑模式高性能数据表 | 表格在暗黑主题下对比度符合 WCAG AA 对正文/大字的底线；支持列排序或等价重排、固定关键列或横向滚动不丢上下文；1k 行级演示数据滚动时无明显掉帧（或与 M01 协调使用虚拟化策略） | 暗黑模式下关键文字与网格线不可辨；排序后状态与图表不一致且无提示 | 行级 hover/选中态与表头操作有克制的状态动画；与全局 neumorphism 阴影体系一致 |
| M05 | 全局加载与渐进呈现 | 首屏与每次重查询具备骨架屏、进度或分阶段文案之一；重操作可取消或展示队列状态（若实现取消则必须真取消请求/渲染） | 长时间无反馈或重复点击产生重复提交且无防护 | 加载态与内容态切换有统一时长曲线，避免突兀跳变 |
| M06 | 空状态 | 无数据集、无查询结果、无权限数据三类至少区分两类文案与图示意图；提供下一步动作（示例：调整时间窗、重置筛选、载入演示数据） | 空白区域无说明或仅显示「暂无数据」 | 空状态插画/图形保持软 UI 调性但不牺牲可读性 |
| M07 | 错误恢复 | WebGL 上下文丢失、着色器编译失败、网络超时、部分接口 4xx/5xx 均有独立提示与恢复路径（重试、降级到 SVG/表格、或切换简化视图） | 错误仅以控制台日志呈现或整页崩溃 | 错误横幅与 toast 动效入场一致；恢复后焦点合理回落 |
| M08 | 动效编排 | 全局定义「数据更新 / 导航 / 系统反馈」三类动效的优先级与并发规则（例如图表更新不打断关键加载提示） | 多处动画同时无限循环或阻塞主线程导致交互不可用 | 动效服务于状态理解，时长与缓动在暗黑 neumorphism 下仍清晰 |
| M09 | 响应式可读性 | 在约定断点（见下文）下，核心数据表与至少一类 SVG 视图可完整阅读；WebGL 画布可适配视口或提供明确的全屏/缩放控件 | 小屏仅横向溢出无滚动提示或关键控件不可达 | 断点切换时布局重排有短暂过渡，避免文字截断无省略提示 |

### Should Deliver（S）

| ID | 功能 | 理想形态 | 降级底线 |
|----|------|---------|---------|
| S01 | 语音输入与朗读反馈 | 浏览器支持时使用 Web Speech API 完成口述查询与关键结果播报；不支持或拒权时界面等价于纯文本 | 仅文本输入与屏幕内文案结果，无语音 |
| S02 | 流式/准实时刷新 | WebSocket 或轮询推送增量点，SVG 与表格增量合并更新 | 手动刷新按钮 + 上次更新时间戳 |
| S03 | 视图书签与分享 | 将筛选条件与视图状态编码为 URL 参数或本地快照 | 导出 JSON/剪贴板复制查询条件 |
| S04 | 键盘效率 | 主要查询与表格导航支持快捷键说明面板 | 鼠标可操作全部红线功能 |

### Excluded（X）

| ID | 功能 | 排除原因 |
|----|------|---------|
| X01 | 自动在生产环境执行变更（限流、重启、扩缩容） | 产品定位为诊断与沟通工具，非变更编排系统 |
| X02 | 企业级计费、多租户合同与发票 | 与当前「工程排障」核心目标无关 |
| X03 | 接入任意厂商 APM 的正式商业连接器矩阵 | 交付以可插拔 mock/演示数据源为主，避免范围膨胀为集成项目 |

## 内容意图地图（IA）

### 工作区总览与场景上下文
- **意图**：确认当前分析对象（环境、时间窗、服务/主机粒度）并理解全局健康度。
- **优先级**：P0
- **必须包含**：环境标识、时间范围、关键 KPI 摘要、数据新鲜度或上次刷新时间
- **创作自由度**：content-fixed-layout-free
- **关联契约**：M05, M09

### WebGL 大规模态势层
- **意图**：在体量超出常规 DOM/SVG 舒适区时，仍能获得空间分布或密度类洞察，并与其他视图联动。
- **优先级**：P0
- **必须包含**：图例或度量说明、当前聚合层级或采样策略提示、与下钻目标的关联入口（语义级，非具体按钮文案锁定）
- **创作自由度**：fully-open
- **关联契约**：M01, M07, M08

### SVG 剖析与趋势层
- **意图**：对选定子集做时间或分布维度的精确阅读，并与表格行级记录互证。
- **优先级**：P0
- **必须包含**：坐标含义、单位、当前序列名称或 ID、数据点 hover 可读的最小信息集
- **创作自由度**：content-fixed-layout-free
- **关联契约**：M02, M06, M08

### 结构化证据表
- **意图**：排序、对比、复制关键字段，支撑工单或复盘材料。
- **优先级**：P0
- **必须包含**：与图表联动的键、主要度量列、异常标记或阈值提示（若数据源提供）
- **创作自由度**：content-fixed-layout-free
- **关联契约**：M04, M06, M09

### 自然语言与语音查询
- **意图**：用口语化目标替代多步点击构建复杂筛选。
- **优先级**：P1
- **必须包含**：解析结果确认区、历史查询或建议词条占位（可为空状态）、麦克风权限说明
- **创作自由度**：fully-open
- **关联契约**：M03, S01, M07

### 系统状态与诊断反馈
- **意图**：理解当前是加载、空、错、还是降级模式，并知道下一步怎么做。
- **优先级**：P0
- **必须包含**：错误码或原因分类（用户可读）、重试/降级选项、联系数据源或检查项的简短指引
- **创作自由度**：content-fixed-layout-free
- **关联契约**：M05, M06, M07

## 响应式优先级

- **desktop-first**：主工作流假设为宽屏多栏：WebGL 与 SVG、表格同时可见；性能敏感交互（框选、密集 hover）以指针设备为优先验证路径。
- **balanced（次级）**：平板宽度断点（约 768–1024px）下允许折叠为「主画布 + 抽屉式详情」，但表格与一类 SVG 必须仍可达；手机宽度（<768px）以只读摘要 + 单一主视图为底线，语音/文本查询仍可用。
- **关键要求**：断点切换时不得丢失未提交的查询草稿；WebGL 在窄屏可降低默认粒子/点数但须提示当前为简化模式。

## 技术约束

- 同时存在 WebGL 与 SVG 渲染路径，需约定主线程预算与降级策略（例如 WebGL 不可用时自动切换聚合 SVG）。
- 自然语言解析可为前端规则 + 后端 mock 或轻量意图模板，须暴露「机器可读的查询结构」供调试与复现。
- 暗黑模式为默认或一键切换之一，表格与图表色板需共用 token，避免独立硬编码。
- 语音能力依赖浏览器能力与用户授权，不得阻塞文本路径。

## 设计约束

- 全局采用 **Neumorphism（新拟态）软 UI**：同一光源方向、一致的凹凸与阴影半径阶梯；暗黑模式下通过降低环境对比、提高控件边缘分离度维持可访问性。
- 工程类信息优先保证可读性与状态对比，软 UI 装饰不得削弱错误/加载/空状态的识别度。
- WebGL 与 SVG、表格的强调色与中性色应来自同一套语义色板（正常/警告/严重），保证跨视图一致性。
