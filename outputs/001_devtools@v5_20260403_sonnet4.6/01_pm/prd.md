# DevTools 系统性能分析工具 PRD

## 核心问题定义

这个产品帮助**后端/全栈开发者**在**生产故障排查与日常性能调优场景**下解决**系统性能瓶颈难以快速定位**的问题，让他们能**在数分钟内精确找到瓶颈所在，理解其成因，并做出数据支撑的优化决策**。

---

## 用户与场景分析

### 用户类型

- **主力用户**：后端工程师 / 全栈工程师（3-10 年经验）
- **次要用户**：SRE / DevOps 工程师、技术 Lead

### 使用场景

1. **紧急故障排查**：生产环境告警，CPU/内存/延迟异常飙升，需要快速缩小范围
2. **日常性能调优**：迭代上线前后做 baseline 对比，发现回归
3. **容量规划**：分析历史趋势，预判资源瓶颈时间窗口

### 痛点

- 指标数据分散（APM / Prometheus / 日志系统三套工具切来切去）
- 大数据量图表渲染卡顿，刷新一次等 3-5 秒
- 只有折线图，缺少跨维度关联分析（CPU 高是哪个进程？进程忙在哪个调用链？）
- 靠肉眼扫描数据表格，漏掉异常行

### 目标结果

- 打开工具 30 秒内能看到全局健康状态
- 可以用自然语言描述问题（"找出过去 1 小时 P99 延迟最高的服务"）而不用写 PromQL
- 表格/图表联动：点击图表异常区域，表格自动高亮对应记录

---

## 设计意图

- **情绪目标**：打开即建立掌控感——数据清晰有序，不焦虑、不混乱；深入分析时进入"专注流"状态
- **信息密度**：high（工具类，数据密集，需要高扫描效率）
- **交互深度**：immersive（WebGL 渲染 + 图表联动 + 自然语言查询 = 深度交互系统）
- **视觉信任感**：professional（专业工具感，不是消费品，避免过度装饰）

## 功能契约

### Must Deliver（M）

| ID | 功能 | 验收条件 | 失败条件 | 表现力目标 |
|----|------|---------|---------|-----------|
| M01 | WebGL 大数据量指标渲染 | 渲染 10 万+ 数据点（模拟），帧率稳定在 ≥30fps；时间轴可缩放（鼠标滚轮/手势） | 帧率掉到 15fps 以下或无法缩放 | 暗色背景下数据线发光效果，密集区域自动降采样但保留峰值极值 |
| M02 | 动态 SVG 图表区块 | 至少实现折线图+面积图+柱状图三种类型，支持 hover tooltip，支持点击图表区域触发联动 | hover 无响应或点击后列表无变化 | 图表入场时有流畅 path 绘制动画（500ms draw-on），tooltip 有平滑过渡 |
| M03 | 自然语言查询接口 | 支持至少 5 种预设 query 模板（延迟/吞吐/错误率/CPU/内存），可手动输入，输入后页面过滤数据 | 输入后数据无变化 | 搜索框有 token 气泡解析视觉（把 "P99 > 100ms" 拆成高亮 tag），查询结果有过渡动画 |
| M04 | 高性能数据表格（暗黑模式） | 支持虚拟滚动（渲染 1000+ 行不卡顿），支持列排序，支持关键词高亮，异常行自动标红 | 滚动卡顿或排序无效 | 异常行有脉冲式边框动效，排序切换有行重排动画 |
| M05 | 图表与表格联动 | 点击图表中某时间段/某数据点，表格自动过滤到对应时间窗口内的记录，并高亮异常 | 点击图表后表格无变化 | 联动时有"焦点光束"从图表指向表格的视觉引导 |
| M06 | 导航与视图切换 | 顶部/侧边导航可在"总览/服务详情/历史趋势/查询控制台"间切换，切换有过渡动画 | 点击导航无反应 | 视图切换有 fade+slide 复合过渡（200ms） |

### Should Deliver（S）

| ID | 功能 | 理想形态 | 降级底线 |
|----|------|---------|---------|
| S01 | 语音控制接口 | Web Speech API 录音，转文字后触发查询 | 仅展示麦克风图标+模拟"正在识别"动效，不接真实 API |
| S02 | 暗黑/亮色主题切换 | 全局切换，所有图表/表格/背景同步更新，有平滑过渡 | 仅切换背景和文字色，图表颜色不更新 |
| S03 | 告警面板 | 实时（模拟轮询）推送告警卡片，支持关闭/查看详情 | 静态告警列表，有 badge 数字 |
| S04 | 性能趋势对比 | 两个时间段并排对比图 | 仅单时间段展示 |

### Excluded（X）

| ID | 功能 | 排除原因 |
|----|------|---------|
| X01 | 真实后端 API 接入 | 单文件 HTML 无后端，全部使用模拟数据；与产品核心目标（展示交互能力）无关 |
| X02 | 用户登录/鉴权 | 超出本次原型范围 |
| X03 | 数据持久化存储 | localStorage 可用于主题偏好，不做完整持久化 |

## 内容意图地图（IA）

### 全局导航

- **意图**：在 4 个主要视图间切换，始终知道当前位置
- **优先级**：P0
- **必须包含**：当前视图标记、4 个视图入口（总览/服务详情/历史趋势/查询控制台）、告警 badge、主题切换开关
- **创作自由度**：content-fixed-layout-free
- **关联契约**：M06, S02

### 总览仪表板（Hero 视图）

- **意图**：30 秒内看懂当前系统健康状况——哪些服务有问题、严重程度
- **优先级**：P0
- **必须包含**：系统健康评分（数字+颜色编码）、Top 5 异常服务列表、全局吞吐/延迟/错误率趋势迷你图、实时告警数
- **创作自由度**：content-fixed-layout-free
- **关联契约**：M02, M03, S03

### WebGL 指标大盘

- **意图**：深度分析时间序列数据，发现峰值和异常区段
- **优先级**：P0
- **必须包含**：时间轴（可缩放）、多指标折线（CPU/内存/延迟/吞吐）、异常区段标注、联动触发器
- **创作自由度**：fully-open
- **关联契约**：M01, M05

### 高性能数据表格

- **意图**：精确查看具体记录，快速定位异常行
- **优先级**：P0
- **必须包含**：服务名/时间戳/延迟/错误率/状态列、异常行高亮、关键词搜索、列排序、空状态、加载态
- **创作自由度**：content-fixed-layout-free
- **关联契约**：M04, M05

### 自然语言查询控制台

- **意图**：用问题描述而不是代码语法查询数据
- **优先级**：P1
- **必须包含**：查询输入框、预设 query 快捷标签、token 解析视觉、查询结果摘要、历史查询列表
- **创作自由度**：fully-open
- **关联契约**：M03, S01

### 告警面板（浮层/侧边）

- **意图**：不中断主流程地获知新告警
- **优先级**：P1
- **必须包含**：告警卡片（级别/服务/时间/描述）、关闭/查看详情操作、空状态
- **创作自由度**：fully-open
- **关联契约**：S03

## 响应式优先级

**Desktop-first**：核心用户在大屏工作站/多显示器环境操作，移动端为二级支持（查看总览告警），关键断点：
- `≥1280px`：完整三栏布局（侧边导航 + 主内容 + 告警边栏）
- `768-1279px`：两栏（折叠侧边导航 + 主内容）
- `<768px`：单栏，底部 tab 导航，隐藏复杂图表面板

---

## 技术约束

- 单文件 HTML + Tailwind CDN + 原生 JS，无构建工具
- 第三方库通过 CDN 引入（Three.js / WebGL 或 Canvas / GSAP / D3.js 等按需）
- 所有数据使用 JS 内联模拟数据，不依赖外部 API

---

## 设计约束

- 必须支持暗黑模式（主色调为暗色，亮色模式可选）
- 新拟态（Neumorphism）风格作为参考方向，但需与高信息密度需求权衡——纯 Neumorphism 在深色 + 高密度场景下可读性极差，Designer 需要做风格再诠释（建议：用 Neumorphism 的"内凹/浮凸光影"作为局部组件处理手法，而非全页面铺设）
- WebGL 视觉层不能遮挡核心数据文字
