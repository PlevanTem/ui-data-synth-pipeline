── STAGE 1 · Frame a Question · 锚定问题 ──────
【HMW问句探索】
原始需求表面是「做一块监控鉴定量、防积压的数据看板」，但真正张力在于：法医鉴定链条里，管理者要在证据保全、程序合规与排期现实之间做取舍；数据若只展示「总数」，会把人的焦虑转移到屏幕上，却不回答「此刻该把资源押在哪」。受影响者包括：排案调度员（怕错过法定时限）、技术主检（怕复杂案被误判为简单案插队）、委托方与当事人（对等待的解释权薄弱）。因此问题不能只框成「展示更多图表」，而要锚定「谁在什么时刻需要何种可行动判断」。

三个不同角度的 HMW：
1）我们如何能让调度员在早晨站会前 90 秒内，判断「未来两周哪类技术路线会吃满产能」？
2）我们如何能让主检在个案复核时，把「伤害分布与历史同类案」对照成可辩护的叙事，而不是一串孤立比例？
3）我们如何能让监管/质控负责人在不侵入个案细节的前提下，看见「管道哪里变细、哪里回涌」？

【选定 HMW】
最具创新潜力的是第 1 条与第 3 条的交集：把「时间序列 + 管道 + 预估器」绑成一条「产能—时限—风险」的共同语言，让管理者从「看报表」转为「做取舍」。意外转折：积压往往不是总量爆炸，而是某类技术复杂度的隐性排队；因此问题框架应从「防积压」升级为「让隐性排队在变成事故前被命名」。

── STAGE 2 · Gather Inspiration · 汇聚灵感 ────
【用户场景】
场景 A：周一晨会前，调度员拖动 Header 时间窗，发现近 30 天某类复杂鉴定折线抬头，但 KPI 卡仍显示「在办总量」平稳——她真正需要的是「哪条技术分支在吃增量」，否则会议会变成互相指责。场景 B：主检打开伤害分布环形图，不是为了好看，而是要在专家会商前快速定位「非常见损伤组合」是否被系统归错类。场景 C：质控在管道区看到桑基里「退回补材」突然变粗，情绪从麻木变成警觉：这不是效率问题，而是上游委托材料质量在塌方。

【极端用户洞察】
重度使用者：每天切换时间窗十几次、把 hover 当「临时放大镜」的技术主检——他们会对 loading 与图例切换的延迟极度敏感，延迟会逼他们回到 Excel。完全不用的人：只收纸质月报的院领导——若故事不能压缩成「一张图讲清风险」，他们会认为看板是科室玩具。冰山之下：表层是「看图」；深层动机是「把我的专业判断外包给可信的视觉证据」；根本信念是「数据若不能上庭、不能进纪要，就不值得信」。

【关键 Insights】
1）人们真正要的不是更多维度，而是「哪一条线在说谎」——当折线与漏斗矛盾时，界面要暴露矛盾而非粉饰。2）人们真正需要的是把「预估完成区间」与「法定/约定期限」叠在同一时间轴语义里，否则预估器只是安慰剂。3）人们真正恐惧的是「系统给出一个乐观区间，却在两周后推翻」——loading 与不确定性区间必须同事出现。4）人们真正渴望的是管道区能回答「卡在哪一站、谁该动」，而不是只展示流量美学。

── STAGE 3 · Synthesize · 合成行动洞察 ────────
【Persona】
姓名：林岚（调度主管，非法医出身但懂流程）。一句话：她要用有限人力接住不断变化的委托结构。核心需求：早会前得到「未来两周哪类案会顶到天花板」的可行动结论。最大恐惧：把简单案排满导致复杂案静默超时，事后被审计追问「当时屏幕上看不出吗？」

【旅程关键时刻】
旅程中最紧张一刻：她在 Header 改时间窗后，主区左折线右环形同时刷新——若右侧分类与左侧序列的口径不一致，她会当场失去对系统的信任，并改用口头协调，数据看板退化为装饰品。

【设计机遇点】
在「时间窗变更 → 全页联动刷新完成」这一瞬间，为林岚这类人解决「口径一致 + 异常先声夺人」的张力：KPI 卡必须声明统计口径；管道与预估器必须共用同一时间语义；环形图分类维度必须与「技术复杂性」标签同源。机遇：把「联动」从交互炫技改为「信任契约」。

【迭代 HMW】
我们如何能在时间窗变化后的同一刷新周期内，让管理者同时看到「总量节奏、结构偏移、管道回涌」三件事，并在任一矛盾出现时得到显式提示而非自行脑补？【↩ 回溯修正 Stage 1】原 HMW 偏「产能」；补上「时限叠合」后更贴近法医场景的法定义务压力。

── STAGE 4 · Generate Ideas · 发散创意 ─────────
【技法触发说明】
类比：借鉴空中交通管制的「跑道占用时长」思维，把鉴定步骤看成起降窗口，用颜色编码占用接近上限的环节。极端假设：若未来 48 小时内所有「高复杂」案必须翻倍到达，管道哪一段会先断裂？界面用沙色高亮「先断点」。反向：故意设计「隐藏最糟情况」的看板会如何？——隐瞒退回率、模糊预估区间；反过来即方案：显式展示退回率与预估置信边界。

【原始创意 × 12】
1）「矛盾探针」：当折线上升但漏斗出口变窄，自动弹出对照卡片解释可能口径差异。2）「时限条」叠在折线背景：把法定/合约节点画成灰带，折线穿越灰带即预警。3）环形图内圈为解剖区域、外圈为致伤工具类型，双击切换层级。4）桑基边宽绑定「等待时长」而非仅件数，让积压可视化在边上。5）「主检书签」：hover 某段折线可钉住该时段典型案例编号（脱敏）供会后跟进。6）管道区提供「如果减少 10% 补材退回」的轻量模拟滑条（不接真实排程，只教育结构）。7）底部预估器用区间带 + 上次预测误差，避免点估计神话。8）图例切换时保留「幽灵曲线」半秒，帮助眼睛追踪系列变化。9）KPI 卡四宫格固定：在办 / 本周新增 / 超期风险 / 补材滞留——避免万能卡。10）时间线预估器与 Header 窗做「父子锁定」图标，防止用户误以为预估覆盖全历史。11）「复杂案呼吸灯」：主区右侧环形中某扇区若周环比异常，用低频脉冲提示而非弹窗。12）晨会模式：一键折叠装饰，只留 KPI+折线+漏斗三件套。

【2×2 矩阵筛选】
X 轴：可行性（低到高）；Y 轴：冲击力（低到高）。
低可行低冲击：纯装饰动效、与口径无关的 3D。
低可行高冲击：全自动排程优化引擎（超出看板边界）。
高可行低冲击：仅换配色主题。
高可行高冲击：矛盾探针、时限灰带叠绘、桑基边宽=等待时长、预估区间+历史误差、图例幽灵曲线、晨会模式。

【Top 3 创意】
Top1：矛盾探针 + 口径声明（解决信任断裂）。Top2：桑基边宽绑定等待时长 + 漏斗/桑基切换（解决「积压藏在哪」）。Top3：预估区间 + 历史误差 + loading 同事出现（解决预估器可信度）。

── STAGE 5 · Make Tangible · 原型具象 ──────────
【Prototype A — 矛盾探针】
形式：Figma 可点击原型 + 3 张故事板。核心体验 30 秒：林岚拉动时间窗 → 折线与漏斗短暂「打架」→ 屏幕右上角出现探针条「新增主要来自 X 类；出口变慢因 Y 环节」→ 她点一下展开口径说明。要验证的假设：用户愿不愿意阅读 2 行解释而非直接骂系统。学习问题：她是先点探针还是先打电话问技术？情绪预测：惊喜（终于有人把矛盾说破）、困惑（若解释仍 jargon）、抵触（若觉得系统在甩锅给委托方）。

【Prototype B — 等待时长桑基】
形式：纸质泳道 + iPad 线框。核心体验：从「受理」到「签发」拖动，边宽随等待时长变化，hover 显示中位天数与 90 分位。假设：边宽比件数更能驱动晨会行动。学习问题：法医团队能否接受「等待」作为道德中性的度量。情绪：惊喜（看见隐形水库）、困惑（补材是否算等待）、抵触（怕被绩效化）。

【Prototype C — 诚实预估器】
形式：可滚动低保真线框（底部/侧边布局各一版）。核心体验：输入关键参数占位 → loading 出现同时展示「上次同类预测误差分布」→ 输出区间而非单点。假设：展示误差会提高信任而非吓跑用户。学习问题：用户是否把误差当作免责条款。情绪：惊喜（终于不装全知）、困惑（区间太宽怎么办）、抵触（委托方看见区间会焦虑）。

── STAGE 6 · Test to Learn · 测试学习 ──────────
【测试问题设计（观察性）】
A 组：请你在不看帮助的情况下，用看板判断「未来两周最可能先堵的是哪一环节」，并说出你依据的三条视觉证据。B 组：当你发现折线与漏斗趋势相反，你的第一反应操作序列是什么？C 组：在预估器 loading 时，你眼睛停在哪里、是否阅读误差提示？

【失败场景预演】
失败 1：用户完全忽略探针，直接认定「数据错了」——迭代：探针改为「必须确认已读」会太重，应改为在 KPI 卡上同步一句人话摘要 + 一键导出截图给信息科。失败 2：等待时长桑基被解读为个人绩效排名——迭代：默认脱敏聚合到「岗位池」而非个人，并加伦理说明开关。

【学习日志】
证实：口径不一致是信任崩塌主因；区间预测+误差披露比单点更能留住专家用户。打破：原以为更多 hover 细节会更好，实则主检在会议场景更需要「少而硬的三证据」。下一迭代最重要改变：把「时间窗—口径—导出」做成同一肌肉记忆路径。

【迭代版本说明】
推荐方案从「炫联动」改为「联动 + 矛盾可读 + 伦理安全默认值」：桑基展示池级等待；预估器默认区间；探针与 KPI 人话绑定。

── STAGE 7 · Share the Story · 故事传播 ────────
【英雄之旅叙事】
现状痛苦：林岚的晨会建立在碎片电话与互相矛盾的表格上，转折点是她第一次在统一时间窗下看见「折线、结构、管道」说同一种话；方案带来的变化不是屏幕变多，而是「隐性排队被命名、矛盾被摊开、预估敢于承认不确定」；未来图景：鉴定中心把看板当成质控与排程的共同文本，争议从「谁记错了数」转向「下一步调整哪条池子容量」。

【价值主张一句话】
ForensicAppraise 让法医鉴定管理者在同一时间语义下，看见总量、结构与管道回涌，并用可核对的口径与诚实区间支撑晨会与风控决策。

【利益相关者沟通语言】
对科室主任：「少一次会后扯皮，多一张可对齐的证据页。」对信息科：「联动规则写清口径字段，便于审计追溯。」对主检：「hover 与图例是为会诊节奏服务，不是为炫技。」对委托方接口人：「区间不是推脱，是把不确定讲在前面。」

【长期影响图景】
若规模化成功，行业会形成「鉴定排队可视化伦理」：等待可被讨论但不被滥用为绩效鞭子；法定时限与内部产能共用一种图形语言，减少隐形挤压；年轻法医在训练期就能从看板读到系统思维而非仅靠师徒口传。
