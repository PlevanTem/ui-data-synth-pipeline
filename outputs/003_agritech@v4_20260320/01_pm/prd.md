# AgriFlow Command PRD

## 一句话定义
这个产品帮助区域农业运营经理与农场协同团队在多地块并行作业场景下解决资源调度不均、响应滞后与信息割裂问题，让他们能实时均衡人机料投入并稳定提升产量与作业效率。

## 推理记录

### 用户与场景分析
- 主要用户是区域农业运营经理、农场调度员、现场作业负责人，分别对应战略调度、流程执行、现场响应三个层级。
- 使用场景具有高频、强时效、跨区域特征：同一时段多个地块并行作业，资源状态快速变化，决策窗口短。
- 显性痛点是“资源调度不均”；隐性痛点是数据源分散导致判断延迟、跨团队协同断裂、错误调度成本高。
- 用户真正目标不是“看图表”或“拖拽节点”，而是形成可闭环的“发现问题-调整策略-验证结果-确认执行”操作链。

### 核心问题定义
农业多地块协同调度的核心问题不是单点数据缺失，而是“态势感知、流程编排、空间验证、决策执行”四环节脱节。产品需要把这四环节压缩进一个连续交互界面，降低决策往返成本与执行误差。

### 实体与功能推导
#### 实体清单
- `resource_unit`：农机、人力、物料等可调度资源，关注容量、可用窗口、地理位置、健康状态。
- `task_order`：作业任务，关注优先级、资源配比、截止时间、状态。
- `farm_zone`：地块与区域，关注边界、土壤指数、天气风险、热度。
- `workflow_node`：流程节点，承载规则条件与动作输出，组成工作流图。

#### 功能清单（显性 + 隐性）
- 显性功能：
  - 动态 SVG 图表与筛选联动（态势判断）。
  - 拖拽式工作流编辑器与自定义节点（策略编排）。
  - 实时地图追踪 + 热力图 + 轨迹（空间验证）。
  - 高转化落地页与 CTA 表单流程（商业转化）。
- 隐性功能：
  - 加载/空态/错误态三态反馈。
  - 模块间状态同步与全局提示（toast、发布反馈）。
  - 交互动效编排、可访问性焦点、reduced-motion 降级。
  - 响应式策略（移动端导航、模块折叠与可读性保障）。

#### 数据交互清单
- 用户读：区域失衡指数、任务指标、筛选后图表。
- 系统实时推：设备/团队位置与热区变化。
- 用户写：工作流节点编辑、发布/回滚、CTA 表单提交。
- 异步验证：工作流模拟、规则校验、发布反馈。
- 依赖关系：先加载 schema 与 telemetry，再支持流程编辑与地理联动。

#### 功能架构
- `situational_command`：总览与告警，依赖地图与分析引擎。
- `workflow_orchestration`：流程编辑与发布，依赖规则引擎。
- `geo_tracking`：位置流与热力层，依赖 telemetry 通道。
- `conversion_landing`：价值叙事与留资转化，依赖指标支持。

### 非功能需求推导
- 性能感知：首屏 2 秒可感知，关键实时刷新 1 秒级反馈。
- 视觉信任：高科技蓝黑冷色调，强调专业与可靠，不走娱乐化“炫技霓虹”。
- 交互密度：高密度信息 + 高交互深度（immersive），必须通过分层反馈避免认知过载。
- 情绪目标：进入即“冷静可控”，使用过程保持“局势在掌控中”。

### 取舍说明
- 将“场景化滚动叙事”和“模板库持久化”放入 S：重要但允许在可视化和基础可用前提下有限降级。
- 将“支付系统”“完整 i18n 平台”放入 X：与本轮核心目标（调度闭环 + 转化验证）弱相关。
- 明确隐性能力（状态反馈、可访问性、异常恢复）为 M 类红线，不作为可选优化项。

## 执行契约摘要
- Must（M）：M01 动态图表联动、M02 工作流编辑器、M03 实时地图热力、M04 CTA 转化流程、M05 跨区块状态流转、M06 隐性体验底座。
- Should（S）：S01 滚动叙事增强、S02 工作流模板复用。
- Excluded（X）：X01 计费支付、X02 全量国际化。
- 详细验收条件与 fail_condition 见 `requirement_spec.json`。

## 设计约束
- 统一 high-tech 蓝黑冷色调，保证跨模块一致性。
- 动态视觉服务信息理解，不可遮挡关键数据。

## 技术约束
- 前端必须为 TypeScript + 组件化多文件工程。
- 地图与图表在无后端条件下也需通过模拟数据演示完整状态流转。

## 边界情况
- 弱网或数据中断时：核心模块需降级展示并提供恢复引导。
- 移动端高密度信息：优先任务与 CTA，次级信息折叠下钻。
- 低性能设备：降低粒子/热力刷新频率，并遵守 reduced-motion。
# AgriFlow Command PRD

## 一句话定义
AgriFlow Command 通过可交互数据总览、流程编排和实时地理联动，帮助农业运营团队在多地块并行作业中快速修复资源调度不均并提升整体产能稳定性。

## 推理记录

### 用户与场景分析
- 主要用户是区域农业运营经理、农场调度员与现场负责人，角色分层明显：管理层关注全局均衡与 KPI，执行层关注任务路径与实时反馈。
- 场景是多农场并行、资源异构（人力、设备、运输）且时间敏感；常见触发是天气波动、设备故障、工序延迟引发局部资源拥堵。
- 显性痛点是“哪里失衡、该调什么”判断慢；隐性痛点是工具间切换多、状态断裂、异常处理不透明导致信任下降。
- 用户真正要的是“确定性决策”：在高压条件下仍能看清全局、快速改流程、验证结果并形成闭环。

### 核心问题定义
这个产品帮助区域农业运营经理与农场协同团队在多地块并行作业场景下解决资源调度不均、响应滞后与信息割裂问题，让他们能实时均衡人机料投入并稳定提升产量与作业效率。

### 实体与功能推导
#### 实体清单
- `resource_unit`：设备/人员/车辆等调度资源，关键属性包含容量、可用窗口、当前位置、健康状态。
- `task_order`：作业任务单，包含优先级、资源需求组合、截止时间与执行状态。
- `farm_zone`：地理作业区域，包含边界、风险指数、热度等级。
- `workflow_node`：流程节点（判断、派发、复核等），承载规则逻辑与执行责任。

#### 功能清单（显性 + 隐性）
**显性功能**
- 动态 SVG 图表：展示失衡趋势、资源结构与筛选联动。
- 拖拽工作流编辑：拖拽节点、连线、配置、发布。
- 实时地图热力：点位、热区、路径追踪与对象详情。
- 落地页 CTA：价值叙事、证据模块、留资表单。

**隐性功能**
- 全局状态联动：筛选、选中对象、流程变更在图表/地图/侧栏同步。
- 反馈系统：loading、empty、error、toast、提交状态。
- 动效编排：入场、状态切换、数据刷新过渡，降低认知跳变。
- 响应式与可访问性：移动端导航与关键操作可达，焦点与降级策略可用。

#### 数据交互清单
- 用户读取区域失衡指数并切换筛选（read）。
- 系统持续推送位置与热度（realtime）。
- 用户编辑流程节点与连线（write）。
- 系统异步校验流程并模拟调度结果（async）。
- 用户提交 CTA 表单并触发来源记录（write）。

#### 功能架构
- `situational_command`：全局态势与告警判断中枢。
- `workflow_orchestration`：规则编排与发布闭环。
- `geo_tracking`：空间监控与路径验证。
- `conversion_landing`：信任建立与线索转化。

### 非功能需求推导
- 性能感知：首屏关键信息应快速可见，实时刷新需稳定且不抖动。
- 视觉信任：高科技蓝黑冷色可强化专业感，但需克制霓虹炫技，避免“娱乐化控制台”误判。
- 交互密度：高密度操作场景，必须有清晰状态反馈与最小认知负担。
- 情绪目标：进入时“可控”，操作中“有把握”，完成后“确认已生效”。

### 取舍说明
- 将动态图表、工作流编辑、地图联动、CTA 转化与交互完整性全部设为 M 类，因为它们共同构成“发现问题→执行调度→验证结果→商业转化”核心链路，任何缺失都会造成体验断裂。
- 将“滚动叙事强化”和“模板库沉淀”设为 S 类：它们提升表现力与效率，但在时间受限时可降级，不应阻断主功能验收。
- 排除计费与全面 i18n（X 类），原因是与当前核心目标无直接关联，而非实现复杂度。

## 执行契约摘要
- **Must (M01-M06)**：动态图表联动、拖拽工作流、自定义节点、实时地图热力、高转化 CTA、跨模块状态流转、加载/空态/错误/可访问性。
- **Should (S01-S02)**：滚动叙事增强、可复用流程模板库。
- **Excluded (X01-X02)**：计费订阅、全面国际化。

详细契约见 `01_pm/requirement_spec.json`。

## 设计约束
- 采用 high-tech 蓝黑冷色体系，并保持全链路视觉一致。
- 视觉特效必须强化信息理解，不得遮挡核心指标或 CTA。

## 技术约束
- 最终交付必须为 TypeScript + 组件化多文件前端工程。
- 地图/图表/流程编辑需在前端可演示完整联动（允许模拟数据）。

## 边界情况
- 弱网或数据中断时必须可恢复（重试、降级提示、保底状态）。
- 移动端高密度内容需拆分优先级，避免将桌面信息直接等比压缩。
- reduced-motion 用户需关闭高频动画但保留关键状态反馈。
