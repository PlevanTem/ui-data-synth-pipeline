# PulseForge Dev Performance Studio PRD

## 一句话定义
这个产品帮助性能工程团队在高压排障场景下快速定位系统性能瓶颈，并将复杂数据转化为可执行优化决策。

## 推理记录

### 用户与场景分析
- 主要用户是性能工程师、资深前端/可观测性开发者、技术负责人，技术成熟度高，容忍复杂界面但不能容忍慢反馈。
- 使用触发场景多为线上告警后 5-30 分钟内的应急排障，信息密度高、决策压力大。
- 显性痛点：数据量大导致图形卡顿、定位路径长、跨模块手动切换成本高。
- 隐性痛点：在高压状态下，认知负担大于操作负担；若反馈和状态不稳定，会迅速丧失信任。
- 用户真正目标不是“看漂亮图表”，而是“快速确认瓶颈位置、影响范围与修复优先级”。

### 核心问题定义
这个产品帮助性能工程师在高并发排障场景下解决海量性能数据难以快速定位瓶颈的问题，让他们能在分钟级形成修复决策。

### 实体与功能推导
#### 实体清单
- Workspace：承载团队环境与默认上下文。
- PerformanceRun：一次采样窗口的指标主记录。
- TraceNode：拓扑链路中的可交互节点。
- BottleneckInsight：自动提炼的可执行洞察。
- QuerySession：语音/NL 查询与过滤上下文。

#### 功能清单（显性）
- WebGL 拓扑渲染：缩放、拖拽、节点高亮、详情展开。
- 动态 SVG 图表：hover tooltip、图例切换、时间窗切换。
- 语音 + 自然语言查询：语音录入、文本确认、执行查询。
- 高性能暗黑表格：搜索、排序、筛选、行详情。
- 导航与分析模式切换：Overview / Root Cause / Optimization。

#### 功能清单（隐性）
- 全局状态同步：筛选条件在图、表、洞察卡间一致传播。
- 加载/空态/错误/重试：避免分析链路中断。
- 交互动效编排：视图切换、状态变化具备可理解过渡。
- Reduced Motion 与可访问性：控制眩晕并确保可读性。

#### 数据交互清单
- 读取 workspace 数据 -> 触发图表/拓扑/表格初始化。
- 变更时间窗与筛选 -> 异步重算可视化。
- 语音转写 -> 查询执行 -> 跨模块联动刷新。
- 点击节点/行项 -> 展开详情与建议动作。

#### 功能架构
- Realtime Rendering Core
- Query & Voice Intelligence
- Insight & Visualization
- Dark Neumorphic Data Grid
- Interaction State Hub
- Experience Reliability Layer

### 非功能需求推导
- 性能感知：核心交互反馈 100-200ms 可感知；重绘尽量稳定。
- 视觉信任感：需达到 premium 级专业感，不娱乐化。
- 交互密度：高密度，强调“快速扫描 + 快速下钻”。
- 情绪目标：冷静掌控、明确反馈、避免焦虑。

### 取舍说明
- M 类覆盖核心显性功能 + 关键隐性功能，作为验收红线。
- S 类保留“叙事模式、命令效率、生成式增强”三条弹性路径，允许降级但不允许消失。
- X 类仅排除与本次核心目标无关的组织治理和真实后端工程化。

## 执行契约摘要
- Must Deliver：M01 WebGL 交互拓扑、M02 动态图表联动、M03 语音/NL 查询、M04 暗黑新拟态高性能表格、M05 跨区块状态联动、M06 边界状态体系。
- Should Deliver：S01 分析叙事模式、S02 命令面板/快捷键、S03 参数化生成式背景层。
- Excluded：X01 多租户权限后台、X02 真实后端接入与生产鉴权。

详见 `requirement_spec.json`。

## 设计约束
- 暗色优先，软 UI（Neumorphism）风格统一。
- 高密度信息下优先可读性，不为风格牺牲可扫描性。
- 视觉层次要服务于排障效率而非装饰。

## 技术约束
- 必须采用 TypeScript 组件化前端工程。
- 同时承载 WebGL/Canvas 视觉层、SVG 图表与高密度表格。
- 必须实现真实导航、筛选联动、状态反馈与组件通信。

## 边界情况
- 弱性能设备需降级渲染细节并保留信息可读。
- 语音识别不稳定时必须允许文本编辑确认。
- 空数据/错误/超时场景均需可恢复路径，不能出现“死界面”。
