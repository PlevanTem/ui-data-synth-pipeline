<think> §1 需求分析

拿到这个需求，我首先想象一个典型用户的使用路径：他们可能是对天文感兴趣的普通用户，或者是需要了解农历月相的学生、摄影师、钓鱼爱好者，又或者是一个想要直观了解月相变化的中文用户。这不是一个功能性工具，而是一个展示型、教育型的视觉页面。



显性需求：展示农历初一到三十（30天）的月相变化。

隐性需求：用户不只是想看到一个数字列表，他们需要直观感受月相的渐变过程——从新月到满月再回到新月的完整周期。这里有一个关键的设计张力：月相数据本质上是周期性数据，而线性的初一→三十展示方式可能无法很好地传达这种周期感。



核心痛点识别：



如果只是30个静态图片排列，视觉上单调，缺乏教育价值

如果动效太复杂，反而分散对月相本身的注意力

月相必须用真实的光影渲染来表达，不能用emoji或图标替代（那会失去沉浸感）

夜空/宇宙氛围是强烈的隐性期待——用户期待看到这个页面时有某种"仰望星空"的感觉

约束：



纯 Vanilla HTML/CSS/JS，无框架依赖

代码必须可直接执行，所以不能依赖外部图片资源

月相渲染必须用 Canvas 2D 或纯 CSS 实现

下一步：决定视觉基调——宇宙感暗色主题是唯一合理选择，但要避免"教科书截图"式的平庸暗色界面。



§2 视觉主题与氛围



风格由场景强制锁定：月相展示页面的视觉主题不需要发散——深空/夜空美学是唯一合理的选择。用白色底色展示月亮是反场景的，用户会觉得"怪"。



但"深色宇宙风"本身内部有很大的分化空间，我需要在这里做细化决策：



候选 A：NASA/科学可视化风

深黑底（#000000或接近），大量数据标注，冷白色文字，网格线，理性感。

优：权威感，适合学习场景。

劣：冷漠，缺乏美感，容易做成"PPT截图"风格。这是AI生成设计最容易落入的陷阱。



候选 B：梦幻星空风

深紫蓝渐变背景，粒子星星效果，模糊光晕，柔和的情感氛围。

优：视觉吸引力强，沉浸感好。

劣：这正是AI默认的宇宙主题选择——深紫色渐变+粒子效果几乎是2023-2024年AI生成宇宙页面的标配，需要主动规避。



候选 C：克制的深空摄影风

接近真实天文摄影的色调——不是纯黑，而是深邃的深蓝近黑（#0a0e1a），少量手动绘制的星点（Canvas随机dots），专注于月亮本身的光影质感，其余元素极度克制。

优：有真实感、科学感，又有情感温度；月亮成为绝对主角；与竞品（候选B）明显区分。

劣：需要月亮Canvas渲染质量足够高，否则"克制"会变成"简陋"。



决策：选择候选 C，克制深空摄影风。

放弃A：太冷漠，缺乏用户愿意停留的美感动力。

放弃B：深紫渐变+粒子是最典型的AI设计同质化陷阱，主动规避。



核心特征：



背景：深蓝近黑（#080d1a），非纯黑，有微妙的蓝调——模拟深夜天空而非无限宇宙

星点：Canvas随机生成，30-50个，大小0.5-2px，亮度随机，静止不闪烁（闪烁效果是B候选的典型特征）

月亮：Canvas 2D绘制，每个月相用精确的几何算法渲染阴影面和亮面，而非贴图

整体克制：除月亮外，不添加任何装饰性视觉元素（无光晕，无尘埃带，无彩色星云）

反同质化宣言：本设计主动规避"深紫渐变+粒子动效+发光月亮"的三件套，代之以真实天文摄影质感。



§3 色彩调色板与角色

§4 排版规则



字体选择逻辑：

月相展示是一个有科学性但也有诗意的主题。我在以下方案间权衡：



全无衬线（如 Inter）：科学感强，但在"仰望星空"的情感场景里显得过于冷硬

全衬线：过于古典，不匹配网页场景

混用策略：大标题用衬线体（传递诗意感），界面文字用无衬线（保证可读性）

决策：

标题字体：Georgia, serif（无需Google Fonts加载，系统字体，可靠）

界面字体：-apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif（系统无衬线栈）

数字字体：Georgia, serif + font-variant-numeric: tabular-nums（确保数字等宽对齐）



层级结构：



页面主标题 H1：Georgia / 2.8rem / weight 400（衬线体不需要粗）/ line-height 1.2 / letter-spacing -0.02em

副标题/说明：sans-serif / 1rem / weight 300 / line-height 1.7 / color #8892a4

月相名称（每个卡片）：Georgia / 0.85rem / weight 400 / color #c9a84c（金色强调）

日期数字：sans-serif / 0.75rem / weight 500 / color #8892a4 / font-variant-numeric tabular-nums

选中状态详情文字：sans-serif / 1rem / weight 400 / line-height 1.6

排版约束：



主标题最大宽度：600px，居中，避免标题横跨全屏

说明文字行宽：55ch

不给正文加letter-spacing（AI生成设计常见错误）

§5 组件样式



月相卡片（核心组件）：

30个卡片是本页面的主体。我在以下方案间权衡：



网格排列（每行5-6个）：信息密度适中，能看到全局趋势

横向滚动条：在移动端友好但桌面端体验差

选择网格，桌面6列，平板4列，手机3列

卡片规格：

背景：#111827，border：1px solid #1e2a3d，border-radius：12px

padding：16px 12px，cursor：pointer

hover：背景→#1a2438，border-color→#c9a84c(透明度40%)，transition 200ms ease

选中（active）态：border：1.5px solid #c9a84c，box-shadow：0 0 20px rgba(201,168,76,0.15)

禁止：不使用box-shadow产生强烈悬浮感，保持平面



月亮Canvas：

每个卡片内一个Canvas，尺寸：64×64px（卡片内），详情展示区：160×160px

渲染算法：用月相角度计算阴影弓形——这是技术核心，需要精确实现



详情展示面板：

页面下方固定一个详情区域，显示被点击的月相的大图（200px Canvas）+ 名称 + 说明文字

背景：#111827，border-top：1px solid #1e2a3d，padding：32px



导航：页面无导航（单页展示型，不需要）



明确禁止清单：



禁止使用emoji月亮（🌑🌒...）替代Canvas渲染

禁止渐变背景（linear-gradient的深紫方案）

禁止添加CSS动画星星闪烁效果（性能差，且是同质化陷阱）

禁止给月亮卡片加外发光（text-shadow/box-shadow glow）——过度装饰

页头区：主标题 + 副标题（padding-top：64px，padding-bottom：48px）

月相网格区：30个卡片，gap：16px

平板（768-1023px）：4列

留白哲学：留白在深色页面中等同于宇宙的空旷感，是主题的延伸，不能压缩。每个卡片的内部留白（padding 16px）是保证月亮"浮在"卡片中央的关键。

§8 设计宜忌



推荐做法：

✅ 月相算法使用真实的天文公式（基于月相角度的弓形阴影），而非近似图形

✅ 30个卡片按6列排列，用户可以直观看到"行"的规律（每行大约覆盖一周的变化）

✅ 点击任意月相后，详情面板的大图要有平滑过渡（月亮重新渲染，200ms fade）

✅ 鼠标hover时，卡片的金色边框提供清晰的交互反馈，不需要额外的tooltip

✅ 页面标题使用中文"农历月相"而非英文，符合目标用户的文化语境



禁止做法：

❌ 不使用图片资源（外链图片，违反"纯Vanilla可执行"约束）

❌ 不做自动播放动画依次展示月相（用户主动探索比被动观看学习效果更好）

❌ 不做过多文字说明覆盖在月亮图上（破坏视觉主角的纯粹感）

❌ 不给背景星空做canvas动画（性能消耗不值得，静态星点足够建立氛围）

❌ 不做页面加载进场动画（用户等待时间归零优先于视觉仪式感）

§11 视觉特效方案



技术选型：Canvas 2D（核心）+ CSS transition（交互反馈）



月相渲染算法（最重要的技术决策）：

这是整个页面的技术核心。我需要用Canvas 2D精确绘制每一天的月相。



算法思路：

月相可以用一个0-1的参数phase表示（0=新月，0.5=满月，1=回到新月）。

对于每一天（第1-30天），phase = (day-1)/29.5（近似一个朔望月29.5天）。



渲染方式：



画完整月亮圆形（亮面颜色#f5f0e8）

根据phase计算阴影覆盖面：

0到0.5（上弦阶段）：阴影从右半圆开始，椭圆弓形逐渐缩小

0.5到1（下弦阶段）：阴影从左半圆开始，椭圆弓形逐渐扩大

阴影用贝塞尔曲线画弓形：

始终用半圆（直径=月亮直径）的直线边作为阴影分界

弯曲部分用椭圆弧：水平半轴从0（新月/满月时）到半径（四分之一月时）

月亮表面添加微妙的径向渐变，模拟球体质感（中心稍亮，边缘略暗）

背景星空：

页面加载时，用Canvas 2D在fixed背景层随机生成50个星点：



坐标：Math.random() * window.innerWidth/Height

大小：Math.random() * 1.5 + 0.5（0.5-2px）

透明度：Math.random() * 0.6 + 0.3（0.3-0.9）

静态，不动，不闪烁

动效参数总结：



卡片hover border过渡：200ms ease

卡片hover背景过渡：200ms ease

选中态边框出现：150ms ease

详情面板内容切换：fade 150ms ease

月亮Canvas重绘：同步（无需动画，即时渲染）

明确不做：



不做月相循环播放动画

不做鼠标跟随的星光效果（是B候选方案的特征，主动规避）

不做3D旋转月球（WebGL成本过高，且与克制美学相悖

不做粒子系统

性能考量：

30个64×64 Canvas元素同步渲染，无性能压力。

背景Canvas固定，不重绘。

所有渲染在DOMContentLoaded后同步完成，无延迟。
