# 鸿蒙智联全屋智能中控 PRD

## 一句话定义

这个产品帮助**智能家居用户**在**多设备异构 IoT 环境**下解决**鸿蒙智联设备操控繁琐、无统一管理入口**的问题，让他们能**通过一个极简直观的中控界面统一管理所有设备、编排生活场景、掌握能耗全貌**。

---

## 推理记录

### 用户与场景分析

**谁在用？**
- 主力用户：中产到中高端家庭的成年决策者（25-50岁），已购买华为/鸿蒙生态IoT设备（路由器、摄像头、空调、灯控、扫地机、门锁、窗帘等）
- 技术成熟度：medium —— 熟悉智能手机操作，但不愿意深入学习复杂设置界面；期待"刚好够用"的技术感
- 审美成熟度：medium-high —— 愿意为好看的界面买单，受过华为 EMUI/HarmonyOS 视觉风格训练，排斥杂乱、拥挤的界面
- 次级用户：家庭其他成员（配偶、老人），操作频率低，依赖"一键场景"和语音，对技术细节无感知

**什么场景下用？**
- 日常高频：早中晚切换生活场景（离家/回家/睡眠/观影），出门前确认设备状态，入睡前一键关闭
- 偶发需求：某设备异常时快速定位和处理，查看月度电费、某区域能耗，添加/删除设备
- 环境：手机为主，平板作为家庭共享中控台（固定摆放在客厅），大屏 TV 作为展示屏

**用户痛点（显性）**：
1. 设备多，每个设备要打开独立 App 控制，操控路径过深
2. 场景联动配置复杂，步骤多，很多用户从未成功设置过
3. 不同设备的状态分散在不同界面，无法一眼看到"全屋当前状态"

**用户痛点（隐性）**：
1. 担心设备是否真的执行了操作（反馈延迟焦虑）
2. 家庭成员间没有共享状态通道（老人不知道是否已开灯）
3. 不知道哪些设备耗能异常，无法建立节能意识

**用户真正想要的结果**：
不是"能控制设备"，而是"生活被智能顺畅地服务到，几乎不需要操心设备"。极简控制 = 极大生活自由感。

### 核心问题定义

> 这个产品帮助**拥有多台鸿蒙智联IoT设备的家庭用户**在**日常生活场景切换和设备管理**中解决**设备分散、入口繁琐、场景联动复杂**的问题，让他们能**通过单一中控界面一键切换生活场景、实时掌握全屋设备状态、直观了解能耗**。

### 实体与功能推导

**实体清单（Entities）**：

1. **Device（设备）**
   - 属性：id、name、type（lighting/climate/security/entertainment/appliance）、room、status（on/off/value）、isOnline、lastSeen、powerConsumption
   - 关系：归属于 Room，参与 Scene

2. **Room（房间）**
   - 属性：id、name、icon、deviceIds[]
   - 关系：包含多个 Device

3. **Scene（场景）**
   - 属性：id、name（回家/离家/睡眠/观影/自定义）、icon、actions[]（设备操作序列）、triggerType（manual/voice/auto/time）
   - 关系：关联多个 Device 的状态目标值

4. **EnergyRecord（能耗记录）**
   - 属性：deviceId/roomId、period（day/week/month）、kwh、cost、comparisonToLast
   - 关系：归属于 Device 或 Room

5. **VoiceCommand（语音指令）**
   - 属性：inputText、recognizedIntent、executedAction、timestamp
   - 关系：触发 Scene 或 Device 操作

**功能点清单（Features）**：

显性功能：
- F01：主控仪表盘 —— 一屏看全屋设备状态
- F02：设备卡片控制 —— 点击/长按快速开关和调节
- F03：房间分组视图 —— 按空间过滤设备
- F04：一键场景触发 —— 预设"回家/离家/睡眠/观影"及自定义场景
- F05：场景编辑 —— 选择设备、配置目标状态、命名场景
- F06：语音唤醒控制（小艺集成模拟） —— 语音浮层 + 指令识别反馈
- F07：能耗统计面板 —— 分设备/房间/时段的用电数据图表
- F08：设备详情页 —— 单设备完整参数展示和精细调节
- F09：多端适配 —— 手机/平板/大屏三种布局

隐性功能：
- F10：设备状态实时响应动画 —— 操作后立即有视觉反馈（0-300ms）
- F11：加载与骨架屏 —— 设备列表加载态有结构占位
- F12：空状态设计 —— 无设备/无场景时有引导
- F13：操作成功/失败 Toast —— 每次控制指令有明确结果反馈
- F14：离线设备标记 —— 不在线的设备有明确标识，不可操作时有说明
- F15：响应式导航 —— 手机底部导航/平板侧边栏/TV全屏自适应
- F16：主题/时间段氛围 —— 白天/夜晚自动调整界面色温感知

**数据交互清单**：
- 设备状态轮询（realtime，每5s模拟更新）
- 场景触发（user → write → 批量修改设备状态 → async反馈）
- 语音指令处理（user → write → 意图识别 → 执行 → 反馈）
- 能耗数据加载（user → read → 图表渲染）
- 设备参数调节（user → write → 即时反馈 → 状态同步）

### 非功能需求推导

- **性能感知**：设备卡片操作反馈在 300ms 以内，场景触发有流畅的设备状态逐步过渡动画
- **视觉信任感**：premium —— 用户付出了购买智能家居设备的成本，界面品质要匹配这个消费层级
- **交互密度**：medium —— 卡片式布局，信息密度适中，不超载也不空洞
- **情绪目标**：打开产品时感受到"一切尽在掌握"的沉稳掌控感；夜间使用时有温馨舒适感；操作时有即时响应的"科技感的轻松"

### 取舍说明

- **降级到 S**：场景自动触发（基于时间/位置），因为逻辑复杂但可以做简化 UI 演示
- **降级到 S**：设备添加/配对流程，非核心操控场景，做简化状态演示
- **排除（X）**：真实 IoT API 对接、帐号体系、多用户权限管理 —— 这是原型演示，不是生产系统
- **排除（X）**：推送通知系统 —— 需要 native 能力，Web 原型不实现

## 设计约束

- 遵循 2026 智能家居中控趋势：极简直观、色彩柔和、卡片模块化
- 兼顾华为 HarmonyOS 生态视觉语言（圆角、阴影、柔和渐变）但不直接照搬
- 支持手机/平板/大屏三端，各端有独立布局策略
- 设备卡片是核心视觉语言，需要高度模块化和美观

## 技术约束

- Web 原型，不依赖真实 IoT 接口
- 所有设备状态使用前端模拟数据（mock store）
- 必须使用 TypeScript + 组件框架
- 视觉效果层（能耗图表、环境动效）是竞争力核心，必须实现

## 边界情况

- 离线设备操作：显示"设备离线"状态，操作按钮 disabled，有 tooltip 说明
- 场景执行中：设备卡片进入"执行中"过渡态，逐步显示新状态
- 语音识别失败：模拟返回"未能理解指令"的错误态
- 能耗数据为零：显示"暂无数据"空状态
