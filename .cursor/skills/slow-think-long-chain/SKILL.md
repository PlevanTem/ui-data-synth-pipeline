# 长链推理慢思考 SFT 数据合成

将 `outputs/<case_id>/` 下的全阶段产物，合成为**一条可直接用于 LLM SFT 训练的对话样本**。

## 核心理念

目标格式：

```
User: {自然语言需求}
Assistant: <think>{内心独白式推理过程}</think>

{最终代码实现}
```

`<think>` 块应当是**自然的心理独白**——像一个有设计感的前端工程师在脑中从需求出发、逐步推导出视觉方案的真实过程：有发散、有否定、有收敛、有犹豫。**不是**结构化报告，不是 Q&A，不是角色分工文档。

思维链的核心重量在**需求理解 → 设计方案推导**，技术实现细节轻描。

## 输入

一个 case 目录，包含以下文件（v5 pipeline 标准结构）：

| 路径 | 必需 | 说明 |
|------|------|------|
| `meta.json` | 是 | case 元信息，含 `stack`、`cdn_libs_used`（技术栈上游已定） |
| `01_pm/prd.md` | 是 | 需求推理 + 功能契约 + 信息架构 |
| `02_designer/design_brief.md` | 是 | 设计系统 + 配色 + 排版 + 组件规范 + 视觉特效策略 |
| `03_frontend/index.html` | 是 | 单文件前端源码（HTML + Tailwind CDN + 原生 JS） |
| `03_frontend/self_review.json` | 否 | 自检报告 |

> 实际 pipeline 产出不限于此表，读取时灵活适应。输入核心是：**query → 过程文档 → 最终代码**。

## 输出格式

输出 `<case_id>_long_chain.jsonl`（每行一条，标准 SFT 对话格式）：

```jsonl
{"conversations": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "<think>\n...\n</think>\n\n..."}], "metadata": {"case_id": "...", "domain": "...", "pipeline_version": "v5", "source_case": "outputs/<case_id>", "synth_method": "long-chain-design-v1", "token_estimate": 25000, "stage_files_used": ["meta.json", "01_pm/prd.md", "02_designer/design_brief.md", "03_frontend/index.html"]}}
```

## 执行步骤

### Step 1: 读取全部 case 文件

读取输入表中列出的所有文件，以及 `03_frontend/index.html` 的完整内容。

### Step 2: 构造 user prompt

从 `meta.json` 提取 `input_summary` + `domain`，改写为**自然的用户请求**。

要求：
- 第一人称（"帮我..."、"我需要..."）
- 描述核心痛点和期望效果
- 包含风格/视觉偏好（如有）
- 不含内部术语（pipeline_version、case_id 等不出现）
- 长度 80-200 字

### Step 3: 撰写 `<think>` 推理独白（核心步骤）

这是整条数据最关键的部分。从 pipeline 各阶段文档中**提取决策和推理依据**，重新组织为一段连贯的内心独白。思维链按照**四阶段设计思维模型**展开，但各阶段应自然交织，而非机械分段。

#### 四阶段设计思维模型

**阶段一：需求解构（Deconstruction）**（来源：meta.json, prd.md）
- 业务背景是什么？这是什么类型的产品/页面？
- 目标用户是谁？他们在什么场景下打开这个页面？
- 页面结构：几个区块？信息层级怎么排？
- 核心功能点：哪些是必须做的？哪些是可以剪掉的？
- 从需求中嗅到视觉方向的线索（关键词、情绪、使用场景）

**阶段二：多路发散（Divergent Ideation）**（来源：design_brief.md）
- 头脑风暴 2-3 个视觉风格方向假设，每个方向思考：
  - 配色方案：主色 / 背景 / 强调色的逻辑
  - 排版骨架：网格、对齐方式、留白密度
  - 字体选择：衬线/无衬线、感情色彩、中英文搭配
  - 交互亮点：这个方向下有什么特别适合的交互效果？
- 每个方向写下「这个方向好在哪里 / 有什么问题」

**阶段三：约束验证（Convergent Validation）**
- 对发散出的方向进行自我提问：
  - 符合用户的原始要求吗？
  - 可用性够不够？（对比度、触控区域、信息密度）
  - 视觉逻辑自洽吗？（配色、字体、排版是否互相支撑）
  - 技术可行性：单文件 HTML + Tailwind 能实现吗？有没有特殊效果需要 Canvas/JS？
  - 放弃哪些方向？为什么？

**阶段四：综合决断（Synthesis & Final Decision）**（来源：design_brief.md + index.html）
- 收拢所有线索，输出最终设计决策：
  - 色彩系统：主色、背景色、文字色、强调色及其推导逻辑
  - 排版骨架：容器宽度、节奏、层级
  - 字体系统：字体搭配与情感匹配理由
  - 视觉特效：Canvas / CSS 动效的选择与降级方案
  - 交互重点：哪 2-3 个交互细节最值得打磨
- 技术适配一句话带过（从 meta.json 读取栈，说明设计层面的适配逻辑）

#### 写作风格要求

1. **第一人称心理独白**：「让我想想...」「首先需要搞清楚...」「嗯，这里有个意思的地方...」
2. **自然的思维流**：四阶段不是严格边界，发散和验证可以交织出现
3. **犹豫与比较**：「偏艺术感的手写风 vs. 工整的现代排版...」「等等，这个配色在暗色背景上对比度够吗？」
4. **明确的否定推理**：「不用这个方向，因为...」「这个字体太商务感了，和诗歌节的气质不搭」
5. **回溯与自我纠正**：「刚才想用全白底，但仔细想了下氛围感会很差...」
6. **渐进式细化**：先粗略方向，再逐步深入配色/字体/动效细节
7. **情感化标记词**：「嗯」「啊对了」「等等」「有意思」「关键来了」「差点忘了」
8. **连贯过渡**（不用 markdown 标题分段，用自然过渡句）

#### 关键约束

- **至少 3 个视觉方向的对比/否定**（放弃 X 方向因为 Y）
- **至少 2 次发散→收敛的过程**（A 还是 B？→ 分析 → 选择）
- **至少 2 次回溯**（「等等，刚才那个想法不对...」）
- **不使用 markdown 标题**，只用段落分隔
- **不要 JSON 字段名出现在文本中**
- **技术栈说明轻量化**：一句话，从 meta.json 读取，侧重说明设计适配逻辑
- **长度 3000-8000 中文字符**

### Step 4: 组装 assistant 回复中的代码部分

`</think>` 之后是 assistant 的正式回答，包含完整的 `index.html`：

```
好的，我来为你实现这个{产品名}。

```html
<!-- {case_id}/03_frontend/index.html -->
{完整 index.html 内容}
```
```

### Step 5: 写入 JSONL 文件

将每条样本作为一行 JSON 写入 `<case_id>_long_chain.jsonl`。

## 质量检查清单

- [ ] `user.content` 读起来像真实用户请求，80-200 字
- [ ] `<think>` 块是连贯自然的独白，无 markdown 标题
- [ ] 四阶段设计思维覆盖：需求解构 / 多路发散 / 约束验证 / 综合决断
- [ ] 有 ≥3 个视觉方向的对比或否定
- [ ] 有 ≥2 次发散→收敛过程（A 还是 B？→ 选择）
- [ ] 有 ≥2 次回溯/自我纠正
- [ ] 技术栈说明轻量（一句话，设计层面视角）
- [ ] 包含情感化标记词（嗯、等等、让我想想、有意思...）
- [ ] `</think>` 后有完整 `index.html`
- [ ] 全文无 JSON 字段名泄露
- [ ] 总 token 量 15k-40k

## `<think>` 独白示例（片段）

```
让我先理解一下这个需求。这是一张诗歌之夜的活动票务页面——不是普通的电商购票，而是一个文学活动的入口。用户可能是诗歌爱好者，也可能是被朋友推荐过来的普通人，但共同点是：他们在决定要不要去之前，需要被这个页面打动。

嗯，这不只是功能页，更是一张邀请函。核心信息有：活动时间地点、票价与分区、嘉宾阵容、报名入口。节奏上先给情绪、再给信息、最后给行动。

想想视觉风格——三个方向浮现在脑子里。

第一个：白底书卷感。米白底色，衬线字体，用大量留白营造"翻阅诗集"的阅读感。优点是优雅克制，缺点是太安静了，缺少活动页的张力，用户看了不一定有冲动去买票。

第二个：摄影杂志风。全出血大图，现代无衬线字体，用模特或场地照片做背景。视觉冲击力强，但这个活动没有提供任何摄影素材，硬用占位图会很假。

第三个：深色氛围感。暗底色（近黑或深海蓝），手写字体做标题，点缀金色或暖橘色的发光效果。这个思路有意思——和诗歌之夜的"夜"字契合，暗光、酒馆、凌晨三点读诗，这种氛围感会让人觉得这个活动很特别。

等等，深色方案有个问题要想清楚：票价表和信息区如果全在深色背景上，可读性怎么保证？我得确保文字对比度足够，或者在信息密集区域用半透明卡片做分隔。这个问题可以解决——深色背景 + 信息卡用 rgba 半透明白，应该能维持清晰度。

白底书卷感的问题比较根本——它不够"夜"，跟活动的名字和气质有冲突。摄影风因为没有素材，硬做反而会削弱质感。

那就走深色氛围感。接下来想具体一点：背景色应该是什么深色？纯黑太廉价了，容易显得像某些模仿朋克风的 club 海报。试试深海蓝 #0A0E1A？带一点宇宙感，配合诗歌"探索语言边界"这个意向不错。

字体这块很关键。标题用手写感的衬线字体——Playfair Display 的斜体有那种诗歌印刷体的优雅；正文配 Lora，同是衬线系但可读性更强。中文内容如果有，考虑降级处理。

技术上单文件 HTML + Tailwind CDN 完全够用，Tailwind 的 JIT 能覆盖所有布局需求，Canvas 做一个粒子或噪波背景来增强氛围。

最终决定：深海蓝主题，Playfair Display + Lora 字体组合，金色 #D4A843 作强调色（呼应诗歌/奖项的荣誉感），Canvas 粒子动效做背景层，票价区用 glassmorphism 卡片。

关键交互亮点：标题的 typewriter 效果（逐字显示，营造"正在书写"的感觉）；购票按钮的 hover 光晕；滚动时各 section 的渐入。
```
