# 聚焦决策慢思考 SFT 数据合成

将 `outputs/<case_id>/` 下的全阶段产物，拆解为 **3-5 条独立的 SFT 训练样本**，每条样本聚焦于一个具体的设计或实现决策点，用 `<think>` 独白展示该决策的完整推理链路。

## 核心理念

与 `slow-think-long-chain`（一条长独白覆盖所有决策）不同，本技能生成**多条短而深的推理样本**：

- **长链**：用户问「帮我做一个诗歌节票务页」→ 完整思考整个设计方案 → 输出全部代码
- **因果链**：用户问「帮我做一个诗歌节票务页」→ 聚焦思考某个决策（如配色系统）→ 输出相关代码片段

每条样本的 `<think>` 块更短（500-2000字），但对单个决策的推理更深、更具体。这种数据适合：
- 训练模型在设计决策前先追溯用户需求约束的习惯
- 过程奖励模型（PRM）的 step-level 标注
- 推理蒸馏中的设计感知知识点级数据

## 输入

一个 case 目录（v5 pipeline 标准结构）：

| 路径 | 必需 | 说明 |
|------|------|------|
| `meta.json` | 是 | 含 `stack`、`cdn_libs_used`（技术栈上游已定） |
| `01_pm/prd.md` | 是 | 需求推理 + 功能契约 + 信息架构 |
| `02_designer/design_brief.md` | 是 | 设计系统 + 配色 + 排版 + 组件规范 + 视觉特效策略 |
| `03_frontend/index.html` | 是 | 单文件前端源码（HTML + Tailwind CDN + 原生 JS） |
| `03_frontend/self_review.json` | 否 | 自检报告 |

> 实际 pipeline 产出不限于此表，根据用户提供给你的交付产物灵活适应。核心是：**query → 过程文档 → 最终代码** 制造思维链。

## 输出格式

输出 `<case_id>_causal_chains.jsonl`（每行一条）：

```jsonl
{"case_id": "string", "domain": "string", "pipeline_version": "v5", "sample_id": "sample_01", "focus": "visual_direction", "conversations": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "<think>\n...\n</think>\n\n...\n```html\n...\n```"}], "metadata": {"source_case": "outputs/<case_id>", "synth_method": "causal-chain-design-v1", "stage_files_used": ["meta.json", "01_pm/prd.md", "02_designer/design_brief.md", "03_frontend/index.html"]}}
```

## 执行步骤

### Step 1: 读取全部 case 文件

读取输入表中列出的所有文件，以及 `03_frontend/index.html` 的完整内容。

### Step 2: 构造基础 user prompt

从 `meta.json` 生成一个自然的用户请求（80-200 字），第一人称，包含核心需求和视觉偏好。**所有样本共享同一个 user prompt**（模拟同一个需求下的不同推理焦点）。

### Step 3: 识别决策锚点

从文档和代码中识别 8-15 个可以独立成篇的决策点，每个锚点对应一条 sample。

#### 必选锚点类别（从以下类别中各至少选 1 个）

| 类别 | 示例 | 数据来源 |
|------|------|---------|
| **视觉方向选择** | 为什么选暗色氛围而非白底书卷感，发散→收敛过程 | design_brief, prd, meta 的情绪关键词 |
| **配色系统决策** | 为什么用 #0A0E1A 而非纯黑，强调色选金黄的逻辑 | design_brief 配色部分，index.html CSS 变量 |
| **版式骨架决策** | 为什么 Hero 全屏高度，票价用三列卡片而非表格 | design_brief 排版部分，prd IA 结构，index.html 布局 |
| **功能边界（negative）** | 为什么不做真实支付接口，为什么不接地图 API | prd 功能契约，index.html 中的占位/mock 处理 |

#### 可选锚点类别

| 类别 | 示例 |
|------|------|
| 字体系统选择 | Playfair Display + Lora 的情感匹配逻辑；衬线 vs 无衬线 |
| 视觉特效方案 | Canvas 粒子 vs CSS animation vs WebGL；降级策略 |
| 交互动效编排 | typewriter 效果时序、scroll reveal 参数选择 |
| 组件/区块设计决策 | glassmorphism 卡片 vs 实色卡片；为什么选择 |
| 信息层级与叙事节奏 | 情绪先行还是信息先行；各 section 的顺序逻辑 |
| 响应式策略 | 移动端 Hero 字号缩减逻辑；断点设计理由 |
| 留白/密度决策 | 为什么保持大留白而非信息密铺 |
| 色彩对比度与可用性 | 暗底上文字颜色的对比度计算；是否满足 WCAG |

### Step 4: 为每个锚点撰写 `<think>` 独白

每条独白的写作要求：

#### 结构模式

```
<think>
{引入}：从用户需求中找到与该决策相关的约束和线索
{发散}：列出 2-3 个候选方案并比较各自优劣
{犹豫}：表达某个权衡点上的不确定
{决定}：做出选择并给出核心理由
{细化}：思考具体实现细节
{兜底}：考虑降级/出错场景（如适用）
</think>
```

这不是严格的六步模板——内容应自然流动，允许跳步和交织。

#### 写作风格（与 long-chain 一致）

- 第一人称心理独白
- 情感化标记词（嗯、等等、让我想想）
- 明确的比较和否定
- 不用 markdown 标题
- 不泄露 JSON 字段名

#### 长度与深度

- 每条 `<think>` 块 500-2000 中文字符
- 至少包含 1 个明确的否定推理（放弃了什么方向）
- 至少包含 1 次犹豫/比较（A 还是 B？）
- negative 极性样本（功能边界类）至少 2 条

### Step 5: 为每条样本匹配代码输出

`</think>` 后只包含**与该决策直接相关的 `index.html` 代码片段**（对应 section 或 CSS 变量/JS 函数），不是全部源码。

例如：
- 视觉方向选择 → Hero section 的 HTML + 对应 CSS 变量声明
- 配色系统 → `:root` CSS 变量块 + 相关组件的颜色应用
- 版式骨架 → 对应 section 的 HTML 结构骨架
- 字体系统 → `<link>` 引入 + 字体相关 CSS 规则
- 视觉特效 → Canvas/JS 动效代码块
- 功能边界 → 占位/mock 相关的 HTML 或 JS 代码

代码格式：独立 `html` 代码块，注释标明对应的功能区域。

### Step 6: 组装并写入 JSONL

每条 sample 为一行 JSON。

## 质量检查清单

- [ ] 8-15 条 samples
- [ ] 每条 `<think>` 是连贯自然独白，无 markdown 标题
- [ ] 每条有 ≥1 个否定推理
- [ ] 每条有 ≥1 次比较/犹豫
- [ ] ≥2 条 negative 极性样本（功能边界类）
- [ ] 覆盖 ≥4 种锚点类别（含必选中的视觉方向、配色、版式）
- [ ] `</think>` 后代码只包含决策相关片段（非完整 index.html）
- [ ] user prompt 对所有样本一致
- [ ] 全文无 JSON 字段名泄露
- [ ] 技术栈相关样本（如有）轻量化处理，侧重设计适配逻辑

## `<think>` 独白示例

### 示例 1: 视觉方向选择

```
让我想想这个诗歌节页面的视觉方向。先从需求里找线索——"国际协作诗歌节"，有多国诗人，有评审和奖项，在晚间举行。用户希望有文学气质，不要做成普通电商购票页那种冷冰冰的样子。

这个需求传达的情绪是什么？文学性、仪式感、夜晚、沉浸感。带着这几个关键词我来想风格方向。

第一个方向：白底书卷感。米白底色，衬线字体，用大留白和轻盈的排版营造"翻阅诗集"的阅读体验。优雅、克制、有文学感。但等等——这个活动是"夜"的活动，白底方案跟"夜"这个基调有根本性冲突。而且活动页需要让人产生"想去"的冲动，白底方案太克制了，视觉张力不够，很难在3秒内打动用户。

第二个方向：现代主义拼贴风。高饱和大色块，强烈几何分割，无衬线大标题。视觉冲击力强，时髦，适合艺术装置展或先锋音乐节。但这个审美跟"诗歌"的气质有点偏——如果评审和参演阵容里有严肃的文学诗人，这种海报风格会让活动看起来不够庄重。放弃。

第三个方向：深色氛围感。暗底（近黑或深海蓝），手写感衬线字体，金色或暖橘色作为点缀，营造出"深夜、朗诵台灯光、烛光酒馆"的氛围。这个方向和"诗歌之夜"的"夜"字高度契合。而且暗色背景能让文字真的"发光"——标题和诗人名字在暗底上会有一种自然的灼烧感，符合诗歌"点亮语言"的意向。

嗯，就走深色氛围感。但有个实际问题：暗底上的票价表和详细信息怎么保证可读性？这个需要在实现层面用 glassmorphism 半透明卡片来解决——信息密集区用 rgba(255,255,255,0.05) 的毛玻璃卡片做分隔，既保持暗色调性，又让信息区清晰可读。这个问题可以处理，不是推翻方向的理由。
```

### 示例 2: 配色系统决策

```
视觉方向定了是深色氛围感，现在来想具体配色。

背景色怎么选？第一反应是纯黑 #000000 或者接近纯黑。但纯黑有一个问题——它在屏幕上会显得很廉价，有点像某些 club 海报或者盗版电影网站的感觉。如果要有文学感和高级感，背景色需要有一点"色彩倾向"。

往蓝色方向走——深海蓝 #0A0E1A。这个颜色带着宇宙感和深邃感，配合"诗歌探索语言边界"的气质不错。比纯黑多了一层视觉厚度，但不会抢占注意力。卡片背景用 rgba(255, 255, 255, 0.05) 半透明白，在暗底上形成微妙的层次感。

主文字色不能用纯白 #FFFFFF——纯白和深海蓝背景的对比太强，长时间阅读会有刺眼感。用 #F0EBE0（偏暖的奶白色），一方面对比度足够，另一方面和诗集纸张的米白色有联想感，更符合文学调性。

强调色的选择是关键。金黄色 #D4A843——为什么选金色？因为这个活动有评审和奖项，金色自带"荣誉感"和"优雅感"，跟诗歌印刷体的金边装帧也有联想。而且金色配深海蓝是经典的夜空配色，视觉上稳定好看。CTA 按钮用暖橘 #E87C5A，比纯红更温暖，跟文学气质更搭，在暗色页面上也足够突出。

辅助文字用 #8A8FA8（带蓝灰调的中性色），边框线用 rgba(212, 168, 67, 0.2)——金色边框但透明度降低，只是一条提示性的分隔，不喧宾夺主。
```

### 示例 3: 功能边界

```
用户在需求里提到"报名"和"购票"，但让我想清楚这个功能要做到什么程度。

这是一个展示型的活动票务页——不是真实的电商平台。如果我去接真实支付接口，需要后端 API、用户登录、订单系统、微信支付/支付宝 SDK...这些工作量远超"做一个活动页"的范畴，而且这些全是后端基础设施层面的事，不是前端能独立完成的。单文件 HTML 也根本不适合做这些。

所以报名按钮做成 CTA 锚点或者 href 跳转——点击后可以跳转到假设的外部报名链接，或者直接用 `href="#"` 占位。页面的目标是"让用户想买票"，不是"让用户真的完成购买"。原型展示阶段，这个边界很合理。

同理，嘉宾/评审的介绍区域用 mock 数据——写几个有说服力的假名字和假简介（国籍、获奖经历）。不接任何外部 CMS 或者 API，不做动态加载。静态 HTML 就够了。

这个决定让页面保持零依赖、可在浏览器直接打开，实现目标（展示活动气质、打动用户）完全不受影响。
```
