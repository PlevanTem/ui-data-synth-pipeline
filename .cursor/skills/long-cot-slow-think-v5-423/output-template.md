# 完整设计推理 SFT 样本输出模板

实际输出为 JSONL（见 SKILL.md schema），此模板用于人工审核和示意。一个 case 输出 **1 条** sample，`<think>` 按 11 维度完整推进，**整体遵循三大推理质量准则**（自适应粒度组织、渐进式认知支架、高频严格验证），**并显式穿插 Backtracking 与 Verification 两类带信号词的认知步骤**。

> **维度 2（视觉主题）路径说明**：下方示例的 user query 风格意图模糊（"有文学气质"、"有氛围感"），因此 `<think>` 中对视觉方向做了候选发散。若 user query 已给出明确风格方向（如"极简白底"、"赛博朋克"），应跳过候选发散，直接深化该风格的核心特征和反同质化策略。
>
> **三大准则在示例中的体现**：
> - **自适应粒度**：维度 2（候选发散 + 反同质化）、维度 5（组件冲突 + fallback）段落明显长于维度 7（深度层级）、维度 10（交互清单）等简单推导段落。
> - **认知支架**：关键判断处用"这里的关键是…/核心判断在于…"显式标出 key insight，并在"毛玻璃/backdrop-filter"等概念首次出现时给出一句背景。
> - **高频验证**：除 2 处带信号词的显式 Verification 外，全文散布多处轻量即时自查（"和方向呼应，没问题"、"这个约束后面要用到，先记下来"等），不等积累到阶段末再集中校验。

## User

帮我设计一个国际协作诗歌节的票务/邀请页面。这是一场多国诗人联合朗诵的文化活动，有活动介绍、日期场地、票价分区、评审阵容、奖项说明，还有报名按钮。希望视觉上有文学气质，有氛围感，不要做成普通电商购票页那种冷冰冰的样子。用 HTML + Tailwind 做就好。

## Sample 01: 完整设计推理

### Assistant

```
<think>
先代入这个用户的场景。他在筹备一场文化活动——国际协作诗歌节，是文学圈子里带点仪式感的夜晚聚会，有评审有奖项，不是普通商业演出。他需要的是一个能让人在第一眼就感受到"诗歌之夜"氛围的邀请页，而不是冷冰冰的票务表单。**这里的关键是**：这个页面的首要目标是情绪感染，其次才是信息传递，最后才是票务转化——顺序一旦搞反（比如首屏就是票价表格），文学氛围立刻崩塌。整个设计后续都要围绕这个优先级排。

技术边界先记住：单文件 HTML，使用 TailwindCSS 实现。

软偏好"文学气质"和"氛围感"需要我去解读——文学气质指向历史感、印刷质感、仪式感，不是科技扁平风；氛围感指向沉浸、情绪带入，让人感受到"夜"和"诗"这两个关键词。

风格意图模糊，来发散。候选了几个方向——白底书卷感有文学调但和"夜"正面冲突，而且活动页需要打动人，白底太克制，3 秒内建立不了情绪连接，放弃；拼贴先锋风冲击力强，但和诗歌仪式感气质不搭，评审阵容里有严肃文学背景的人，这个风格会错位，放弃；深色氛围感——暗底加衬线字体加带荣誉感的强调色，让文字有发光感，符合"夜"和"点亮语言"的意向，走这个。

**核心判断在于**：这套方向不能靠"单点风格元素"撑起来，而要让暗底的沉浸感、衬线字体的印刷历史感、强调色的荣誉与仪式感三者互相加持、构成一个整体——任何一个维度后面的决策如果不服务这三者，就是错的，这给后面每一步决策都提供了评判标尺。

反同质化这里要认真想。同类文化活动页最容易落入两类陷阱——要么白底书法元素，要么暗底无衬线粗体加渐变高亮，后者尤其是 AI 生成的通用模板特征。我要在关键决策上有意偏离：背景色往有色彩倾向的暗色走而不是标准深蓝，字体用衬线体，强调色和活动的具体调性挂钩而不是用惯用配色，整体让人感觉是手工调出来的而不是套库的 dark preset。

配色从背景开始推。最直觉的选择是纯黑——但纯黑显廉价，往有色彩倾向的方向微调，具体往哪个色系走要和氛围特征呼应。文字色不用纯白，纯白对比过硬，换成和方向情感联想一致的暖色调。强调色的选择有具体锚点——活动有奖项和荣誉感，这是强调色选择逻辑的来源；CTA 按钮色要和整体调性和谐而不突兀。

验证一下对比度。主文字和背景的对比度要过 WCAG AA（4.5:1）。辅助色在暗底上对比度可能偏低，大概在 3:1 出头——这意味着辅助色有使用限制，只能用在次要信息上，不能用在正文或标题，这个约束后面组件阶段会用到，先记下来。

字体选择。把情感不匹配的选项排除：过于产品化的无衬线字体——少了文学温度；过于学术的经典衬线——像教科书封面，不像活动邀请函。找到和方向特征契合的组合：标题用有印刷历史气质的衬线，斜体很迷人；正文用同系但更克制的衬线，长段落可读性好，调性统一、层次有差异。行距和最大行宽要保证阅读舒适度。字体这一步和刚才定的"三位一体"整体感呼应，没偏。

组件样式。按钮的发光 hover 效果和整体发光氛围呼应。卡片用毛玻璃——毛玻璃这种质感是靠 CSS `backdrop-filter` 模糊卡片后的背景实现的，在暗底上能形成一种"悬浮在夜色之上"的感觉，和文学仪式感很契合，所以初版我倾向用它。等等，这里有个隐患：`backdrop-filter` 在部分低端设备或老版本浏览器上不支持，如果失效卡片直接透明，内容浮在背景特效上可读性会崩。需要回去给这个决策补一条 fallback：用 `@supports` 检测，降级到不透明深色背景，保证内容可读。这个修正要在代码里体现。

布局叙事顺序要情绪先行。第一屏 Hero 全屏，充分建立情绪，不在首屏放票价——太功利，会破坏情绪建立的节奏。section 顺序按"情绪打动 → 认知建立 → 信任背书 → 决策触发 → 价值强化 → 行动引导"的漏斗逻辑来。票价区用卡片而不是表格——表格太功能性，和文学氛围格格不入，卡片可以突出推荐档位。

回头检查叙事节奏——Hero → 介绍 → 评审 → 票价 → 奖项 → CTA。用户心理路径：先被情绪吸引，然后了解活动是什么，评审阵容建立可信度，认同之后触达票价，奖项强化"值得去"，最后行动。这个漏斗成立，继续。

界面的深度与层级，背景特效层在最底，内容层在上，导航在最顶。阴影哲学——暗色系不适合写实阴影，会破坏平面感，用发光高亮替代（按钮 hover 发光外扩，标题有微弱发光）。发光替代阴影这一步和方向里"让文字有发光感"的特征一致，没跑偏。

设计边界要明确，包含功能边界——真实支付做不了，嘉宾信息用 mock 数据，这是合理的原型边界而不是妥协。

响应式。断点策略，移动端布局折叠方案。

不对，等等——我刚才想的卡片内容在移动端两列布局下，信息量大的卡片（比如评审阵容带简介的卡片）在窄屏上会很挤，用户看到的是被截断的内容。需要回去修正组件决策：部分次要信息在移动端隐藏，桌面端才展示完整内容，这样两列布局才是合理的。

交互清单：导航平滑滚动、移动端菜单开合（展开时锁定背景滚动）、卡片 hover 上浮、CTA 发光、scroll reveal 进场动画。这些交互都控制在克制范围内，没有弹跳、晃动之类浮夸动效，和文学仪式感对得上。

特效方案，背景生成式视觉层技术对比——WebGL 方案效果强但引入依赖重，对这种展示页是 overkill；CSS animation 轻量但随机性差，粒子漂移机械；Canvas 2D 在两者之间取平衡，无依赖、性能可控。参数量级上，粒子要若隐若现、不抢主体，颜色和强调色系保持呼应，移动端数量减半避免低端设备掉帧。

让我核查一遍特效决策是否还扣在最初的"三位一体"整体感上：Canvas 粒子的低亮度漂移强化了暗底沉浸感，颜色与强调色呼应、没有引入新色相破坏仪式感，也没有和衬线字体抢视觉焦点——三者互相加持的整体关系没有被破坏，方案成立。
</think>
```

## 审核索引（供人工审核定位）

### Backtracking 与 Verification（两类带信号词的显式步骤）

| 类型 | 位置（维度） | 触发原因 | 修正动作 |
|------|------------|---------|---------|
| Verification | 维度 3（配色）完成后 | 验证主文字/辅助文字对比度 | 确认主文字 OK，辅助色限制使用场景 |
| Backtracking | 维度 5（组件）中 | backdrop-filter 失效导致卡片可读性崩溃 | 补加 @supports fallback 规则 |
| Verification | 维度 6（布局）完成后 | 检查叙事节奏漏斗逻辑 | 确认没问题，继续 |
| Backtracking | 维度 9（响应式）中 | 评审卡片移动端简介文字过挤 | 修正组件决策：移动端 hidden md:block |
| Verification | 维度 11（特效）完成后 | 核查和"三位一体"整体感是否一致 | 三者关系未被破坏，方案成立 |

### 三大质量准则审核锚点

| 准则 | 示例中的对应位置 | 判定要点 |
|------|----------------|---------|
| 自适应粒度 | 维度 2（候选发散 + 反同质化，长段）对照维度 7/10（短段） | 关键推理节点显著长于简单推导节点，全文非等宽平铺 |
| 认知支架（key insight） | 维度 1 "这里的关键是…"；维度 2 "核心判断在于…" | 至少 ≥2 处带显式信号词的 key insight 标出整体方向级判断 |
| 认知支架（概念铺垫） | 维度 5 毛玻璃首次出现时对 `backdrop-filter` 的一句背景解释 | 关键概念首次出现时短句引入背景，不跳步 |
| 高频验证（轻量自查） | 配色验证后"先记下来"、字体段尾"没偏"、深度段尾"没跑偏"、交互清单末"对得上" | 除显式 Verification 外全文散布 ≥4 处轻量即时自查句（不带"验证/核查"等信号词，是随手的整体感对齐） |

## 反面示例

### `<think>` 缺少 Backtracking（错误）

```
配色用深色系，背景 #0A0E1A，强调色金黄，CTA 暖橘。字体 Playfair Display + Lora。
布局情绪先行，Hero 全屏，然后介绍、评审、票价。响应式移动端单列。特效 Canvas 粒子。
```

问题：直接罗列结论，无发散过程，无 Backtracking，无 Verification，无否定推理。这不是推理，是结论的堆叠。

### `<think>` Backtracking 无修正动作（错误）

```
等等，backdrop-filter 在部分设备上可能不支持，这和我的设计有冲突。
不管了，继续往下想布局。
```

问题：发现了矛盾但没有做出任何修正，Backtracking 必须包含实质性的修正动作。

### 违反准则 1：粒度等宽平铺（错误）

```
需求分析：用户要一个诗歌节票务页，需要文学氛围。
视觉主题：定深色氛围风格。
配色：背景 #0F0A14，文字 #E8DCC4，强调色金黄。
字体：Playfair Display + Lora。
组件：按钮发光 hover，卡片毛玻璃。
布局：Hero + 介绍 + 评审 + 票价 + 奖项 + CTA。
...
```

问题：每个维度都是一句话结论，关键取舍（为什么走暗色而不是白底、为什么选衬线、为什么用毛玻璃）和简单推导（色号、字号）用同等篇幅，没有自适应粒度。关键节点必须深度展开，简单节点才保持简洁。

### 违反准则 2：缺认知支架（错误）

```
配色用 #0F0A14 背景，#E8DCC4 文字，#D4A84C 强调。
组件卡片用 backdrop-filter: blur(12px)。
特效用 Canvas 2D 粒子系统，50 个粒子。
```

问题：只写"做什么"不写"为什么"，关键概念（毛玻璃/backdrop-filter）首次出现时没有一句背景说明，关键判断处没有"这里的关键是…"这样的 key insight 标记，读者（以及被训练的模型）无法从这段推理中学到整体判断的逻辑，只能死记答案。

### 违反准则 3：验证过于稀疏（错误）

```
（维度 1-5 全程没有任何自查句）
...
验证一下：对比度过了，继续。
（维度 6-11 又是全程直走，再无回望）
```

问题：全文只在一处做显式验证，其余所有决策一路直走、从不回头对齐前置假设。高频验证要求**即产即验**——定一个色值就顺手核一次对比度、选一个组件就想一下和氛围是否一致、设一个断点就问自己布局是否还成立，轻量自查句要散布全文，不能集中在一两个显式检查段落。
